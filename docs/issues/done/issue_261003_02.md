## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

```json

  "algebra": {},
  "oscillator_generators": {},
  "oscillator_relations": {},
  "central_elements": {},
  "basis": {},
  "parity": {},
```

**`algebra`** — retain concrete dimensions for the selected bosonic rank and
record the C-family parameters and formulas. For example, for C(3) (\(n=2\)):

```json
{
  "family": "C",
  "m": 1,
  "n": 2,
  "cartan_type": "C(3)",
  "alternative_notation": {
    "osp": "osp(2|4)",
    "dimension_formula": "osp(2m|2n)"
```

The rank-specific dimensions are C(2): \(4|4\), total 8; C(3): \(11|8\),
total 19; and C(4): \(22|12\), total 34.

**`oscillator_generators`** — remove the B(m,n) `supplementary_fermion` key.
Use exactly the mandated `fermions` and `bosons` groups:

```json
{
  "fermions": {
    "m": 1,
    "count": 2,
    "labels": ["a_1_p", "a_1_m"],
    "parity": 1,
    "description": "One standard fermionic CAR pair a_1^+, a_1^-."
  },
  "bosons": {
    "rank": 2,
    "count": 4,
    "labels": ["b_1_p", "b_1_m", "b_2_p", "b_2_m"],
    "parity": 0,
    "description": "Bosonic oscillator pairs b_i^+, b_i^- for i=1,...,n."
  }
}
```

For general \(n\), set `rank` to \(n\), `count` to \(2n\), and list both
labels for every \(i=1,\ldots,n\). The fermion `m` is the required
superalgebra parameter, not the number of individual oscillator labels.

**`oscillator_relations`** — define the undeformed CAR, CCR, and vanishing
mixed relations. The deformation terms involving `gb` and \(\kappa\) belong
to Schema 2, not the undeformed Schema 1 relations.

```json
{
  "standard_fermion_anticommutators": {
    "description": "Canonical anticommutation relations for a_1^+, a_1^-.",
    "relations": {
      "same_type": "{a_1^+, a_1^+} = {a_1^-, a_1^-} = 0",
      "conjugate_pair": "{a_1^-, a_1^+} = 1"
    }
  },
  "bosonic_commutators": {

      "same_type": "[b_i^±, b_j^±] = 0",

  }
}
```

**`central_elements`** — make this a top-level object. Store both formal
central symbols, but do not add either to the Lie superalgebra basis; \(K\)
is the scalar identity and \(\kappa\) is the odd nilpotent deformation symbol.
The C(n+1) entry for \(\kappa\) follows this issue's mandatory parity 1 rule.

```json
{
  "kappa": {
    "label": "κ",
    "parity": 1,
    "central": true,
    "nilpotent": true,
    "relation": "κ^2 = 0",
    "in_basis": false
  },
  "K": {
    "label": "K",
    "parity": 0,
    "central": true,
    "relation": "K = 1",
    "in_basis": false
  }
}
```

**`basis`** — use the finalized Issue I01-1 lists and Option A PBW ordering.
The `even` array consists of `H_1` through `H_{n+1}`, followed by
`E_2del{i}_p`, positive pair-root labels, `E_2del{i}_m`, negative sum-root
labels, then mixed-sign pair-root labels (`pm` before `mp`). The `odd` array
contains four labels per \(i\): positive-\(\varepsilon\) `pp`, `pm`, followed
by negative-\(\varepsilon\) `mp`, `mm`, with indices ascending within each
family. For \(n=2\), the arrays are:

```json
{
  "even": [
    "H_1", "H_2", "H_3",
    "E_2del1_p", "E_2del2_p", "E_del1_del2_pp",
    "E_2del1_m", "E_2del2_m", "E_del1_del2_mm",
    "E_del1_del2_pm", "E_del1_del2_mp"
  ],
  "odd": [
    "E_eps1_del1_pp", "E_eps1_del1_pm",
    "E_eps1_del2_pp", "E_eps1_del2_pm",
    "E_eps1_del1_mp", "E_eps1_del1_mm",
    "E_eps1_del2_mp", "E_eps1_del2_mm"
  ],
  "ordering_convention": "PBW: κ < [odd] < [even]; K = 1 is excluded."
}
```

As for B(m,n), neither \(K\) nor \(\kappa\) is part of the `even` or `odd`
arrays; `ordering_convention` documents \(\kappa\) as preceding the
superalgebra basis when the extended basis is in use.

**`parity`** — retain the B(m,n) map from basis label to integer parity.
Every `H_*`, `E_2del*`, and `E_del*_del*` label has value 0; every
`E_eps1_del*` label has value 1. Generate the complete map from the selected
rank's basis arrays so there are no missing or extraneous labels.
