#### Required revision: explicit reverse-order records

The human reviewer correctly identified a completeness gap in the preceding
verification: the prior checker used the oscillator bracket for
anti-symmetry and inferred reverse brackets from the stored canonical-order
records for Jacobi. It therefore did not enforce the Schema 1 requirement to
store all nonzero brackets in both orders. The prior PASS summary does not
establish conformance to that requirement.

I reran a strict in-memory check against the existing JSON records. For every
stored nonzero record `(X, Y, Z, c)` with `X != Y`, it required an explicit
`(Y, X, Z, -(-1)^(p(X)p(Y))*c)` record and checked that any present reverse
coefficient matched. Results:

| File | Existing records | Missing explicit reverse records | Wrong reverse coefficients |
|---|---:|---:|---:|
| `data/C_1_structure.json` | 20 | 20 | 0 |
| `data/C_2_structure.json` | 99 | 99 | 0 |
| `data/C_3_structure.json` | 264 | 264 | 0 |

Thus all distinct-pair records currently lack their reverse-order record; no
coefficient mismatch was found because no such reverse records are present.
For odd-odd pairs the required reverse coefficient is equal to the forward
coefficient; for all other parity combinations it is its negative.

**Root cause:** `compute_bracket_table` in `src/C_generators.py` enumerates
only `left_index <= right_index`, and the JSON serialization emits a record
only for that canonical ordering. The mathematical brackets can be recovered
by graded anti-symmetry, but the generated data is incomplete under the
approved Schema 1 instruction to include all nonzero brackets.

**Proposed remediation after approval:**

1. Update `src/C_generators.py` to emit a record for each nonzero output for
   both `(X,Y)` and `(Y,X)` whenever `X != Y`, with reverse coefficient
   `-(-1)^(p(X)p(Y))` times the forward coefficient. Emit only one record
   when `X == Y`. Keep deterministic ordering and avoid duplicate records.
2. Add `src/verify_C_structure.py` that checks both directions from records
   actually present in the JSON (no inferred reverse entries), validates
   reverse coefficients, compares each directed entry with oscillator
   brackets, and checks Super Jacobi using the explicit directed table.
   Missing records must be reported as failures.
3. Add tests for intentionally omitted/wrong reverse records, regenerate all
   three JSON files, and rerun the complete test suite plus strict pair and
   triple verification for all ranks.
4. Report the new counts and any remaining failure/root cause for human
   review before completion.
