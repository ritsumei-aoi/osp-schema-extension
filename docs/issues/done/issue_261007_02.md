C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.

- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Schema 1 proposal for human approval

I propose documenting the following complete C(n+1) Schema 1 shape in
`docs/json_schema_specification.md`. It keeps the v5.0 structure and field
names used by B(0,n), while replacing the B-specific oscillator and algebra
data as indicated below.

#### Top-level structure and algebra

Keep `schema_version`, `algebra`, `oscillator_generators`,
`oscillator_relations`, `basis`, `parity`, `generator_realization`,
`structure_constants`, and `metadata`. Add `central_elements` as a
top-level key, as required for C(n+1):

```json
{
  "schema_version": "5.0",
  "algebra": {
    "family": "C",
    "m": 1,
    "n": "<bosonic rank>",
    "cartan_type": "C(n+1)",
    "alternative_notation": {
      "osp": "osp(2|2n)",
      "dimension_formula": "osp(2m|2n) with m=1"
    },
    "dimension": {
      "total": "2n^2 + 5n + 1",
      "even": "2n^2 + n + 1",
      "odd": "4n"
    }
  },
  "oscillator_generators": {},
  "oscillator_relations": {},
  "central_elements": {},
  "basis": {},
  "parity": {},
  "generator_realization": {},
  "structure_constants": [],
  "metadata": {}
}
```

`n` is the bosonic rank; for n=1, 2, 3 the even/odd/total dimensions are
4/4/8, 11/8/19, and 22/12/34, respectively.

#### Oscillators and central elements

Replace `supplementary_fermion` with the two required generator groups:

```json
{
  "fermions": {
    "m": 1,
    "labels": ["a_1_p", "a_1_m"],
    "parity": 1,
    "description": "One standard fermionic pair a_1^+, a_1^-"
  },
  "bosons": {
    "count": "2n",
    "n": "<bosonic rank>",
    "labels": ["b_1_p", "b_1_m", "...", "b_n_p", "b_n_m"],
    "parity": 0,
    "description": "Bosonic oscillators b_i^± for i=1,...,n"
  }
}
```

Use `standard_fermion_anticommutators` for the CAR
`{a_1^-, a_1^+} = 1` and `{a_1^+,a_1^+} = {a_1^-,a_1^-} = 0`;
`bosonic_commutators` for `[b_i^-,b_j^+] = δ_ij` and
`[b_i^±,b_j^±] = 0`; and `mixed_commutators` to state that bosons commute
with both fermions. This removes the supplementary-fermion relation.

`central_elements` is top-level, with:

```json
{
  "kappa": {
    "parity": 1,
    "nilpotent": true,
    "central": true,
    "description": "Odd central symbol for the inhomogeneous extension"
  },
  "K": {
    "parity": 0,
    "central": true,
    "identity": true,
    "description": "Even scalar identity; not an independent basis element"
  }
}
```

This follows the issue's fixed parity assignment for κ and K. Neither is an
independent Lie-superalgebra generator in `basis`; K=1 is excluded from the
basis and PBW list. κ records the extension symbol and is not included among
the C(n+1) generators.

#### Basis, parity, and realizations

Use the basis and PBW ordering finalized in `handover/notation.md`:

- `basis.even`: `H_1,...,H_{n+1}`, followed by positive even-root labels
  (`E_2del{i}_p`, `E_del{i}_del{j}_pp`, `E_del{i}_del{j}_pm`), then negative
  even-root labels (`E_2del{i}_m`, `E_del{i}_del{j}_mm`,
  `E_del{i}_del{j}_mp`).
- `basis.odd`: for each increasing i, `E_eps1_del{i}_pp` and
  `E_eps1_del{i}_pm`, followed by for each increasing i
  `E_eps1_del{i}_mp` and `E_eps1_del{i}_mm`.
- For pair roots use lexicographic i<j. `parity` maps every listed basis
  label to 0 (even) or 1 (odd). `ordering_convention` states the finalized
  `[odd: epsilon-positive, epsilon-negative] < [even: Cartan, positive roots,
  negative roots]` convention, with K excluded.

`generator_realization.ordering` lists `a_1_p`, `a_1_m`, then the boson
labels in increasing index and p/m order. `realizations` contains every
basis label in oscillator words using the existing `standard_form` entries
(`words` and rational-string `coeff`), `frappat_form`, and `parity` fields.
Use the formulas in `handover/notation.md`: the Cartan elements are
`H_1=a_1^+a_1^-+b_1^+b_1^-`,
`H_k=b_{k-1}^+b_{k-1}^- - b_k^+b_k^-` for 2<=k<=n, and
`H_{n+1}=-b_n^+b_n^- - 1/2`; even-root realizations use the documented
quadratic boson words, and odd-root realizations are
`a_1^± b_i^±` according to their labels.

#### Structure constants and metadata

Keep `structure_constants` as a list of all non-zero graded brackets for
the selected rank. Each entry retains the v5.0 shape
`{"X": "...", "Y": "...", "Z": "...", "coeff": "...", "sign_rule": "graded"}`.
The specification defines these as computed using the C(n+1) realizations
and CAR/CCR above, not copied from B(0,n).

Keep the v5.0 `metadata` fields (`generated_by`, `generation_date`,
`references`), updating the generator name to a C-specific name when the
data are generated and citing the C(n+1) reference and schema specification.

#### Compatibility and file names

Retain v5.0 field names and value conventions wherever the meaning is
unchanged: `schema_version`, `basis`, `parity`, realization entry structure,

supplementary fermion with a standard fermion pair, and expands the odd basis

interpretation of existing B files.

Use `C_{n}_structure.json`, with n denoting bosonic rank: C(2)=osp(2|2) is
