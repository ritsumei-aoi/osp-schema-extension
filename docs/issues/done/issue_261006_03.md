## Proposal (I03-1) — 2026-10-06 (rev.2: corrected to 10 top-level keys)

### 1. Overview

Implementation via **oscillator algebra simulation** using exact rational arithmetic (`fractions.Fraction`).
Each generator is represented as a sparse `dict[tuple[str,...], Fraction]` (PBW word → coefficient).
Brackets are computed as `[X,Y} = XY - (-1)^{pX·pY} YX` with the product reduced to PBW normal form by
bubble-sort swapping using CAR/CCR:

| Swap rule | Condition | Result |
|---|---|---|
| Fermionic nilpotency | same label adjacent | term → 0 |
| CAR | `a_1_m * a_1_p` | `1 - a_1_p * a_1_m` |
| CCR | `b_k_m * b_k_p` | `b_k_p * b_k_m + 1` |
| Mixed / same boson | `pi*pj=0, different or same` | sign swap, no contraction |

**Bug found and fixed during scratchpad testing**: the initial `_one_swap` only checked nilpotency
inside the swap branch (`oi > oj`). But `a_1_p * a_1_p` has equal PBW indices — never reached the
swap — and propagated incorrectly. Fix: check `if pi==1 and oi==oj: return {}, True` before the
index comparison. All 11 tests pass after the fix.

### 3. Corrected JSON Structure (10 top-level keys per spec §2)

The original proposal used 14 wrong-named keys. The corrected `generate_schema1(n)` produces
exactly the 10 keys specified in Section 2 of `docs/json_schema_specification.md`:

```
schema_version, algebra, oscillator_generators, oscillator_relations,
central_elements, basis, parity, generator_realization,
structure_constants, metadata
```

Key corrections from rev.1:
| Wrong (rev.1) | Correct (rev.2) | Change |
|---|---|---|
| `isomorphism`, `bosonic_rank`, `dimensions` (separate keys) | Merged into `algebra` sub-fields | Merge |
| `parity_assignment` | `parity` | Rename |
| `generator_realizations` | `generator_realization` (no 's') | Rename |
| `car_relations` (top-level) | Inside `oscillator_relations` | Move |
| `cartan_eigenvalues` (top-level) | Removed (spec §3.9 only, not a JSON field) | Remove |
| `deformation_parameters` (top-level) | Removed (not in spec) | Remove |
| `generated_date` (top-level) | Inside `metadata.generation_date` | Move |

Structure constants format: one `{X, Y, Z, coeff, sign_rule}` entry per `(X, Y, Z)` triple.
Multi-term Cartan brackets (e.g., `{pp, mm} = -H_1 - 2·H_2`) produce multiple entries
with the same `(X, Y)` but different `Z`.
