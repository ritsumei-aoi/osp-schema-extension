## Requirements

- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

#### Proposal — Schema 1 for C(n+1)

These definitions follow the finalized I01 basis and PBW order. All ten
proposal sections were approved by the human on 2026-10-10; the specification
was then written to `docs/json_schema_specification.md`.

**Top-level keys and version.** Keep Schema 1 at `"schema_version": "5.0"`.
Retain the B-schema keys `algebra`, `oscillator_generators`,
`oscillator_relations`, `basis`, `parity`, `generator_realization`,
`structure_constants`, and `metadata`; add `central_elements` as a top-level
key.

**`algebra`.** Use `"family": "C"`, `"m": 1`, `"n": n`, and
`"cartan_type": "C(n+1)"`. Keep the existing `alternative_notation` structure
with `"osp": "osp(2|2n)"` and `"dimension_formula": "osp(2m|2n), m=1"`.
For each rank-specific file, store evaluated integer dimensions and also state
the general formulas explicitly:

```json
{
  "dimension": {"total": 19, "even": 11, "odd": 8},
  "dimension_formula": {
    "even": "2n^2 + n + 1",
    "odd": "4n",
    "total": "2n^2 + 5n + 1"
  }
}
```

This illustrates the `n=2` file; dimension values are evaluated to integers
for the rank in each concrete JSON file.

**`oscillator_generators`.** Replace `supplementary_fermion` with exactly the
two generator groups `fermions` and `bosons`. `fermions` has `"m": 1`,
`"count": 2`, labels `["a_1_p", "a_1_m"]`, parity `1`, and describes the
standard CAR pair. `bosons` has `"n": n`, `"count": 2*n`, labels
`b_1_p, b_1_m, ..., b_n_p, b_n_m`, parity `0`, and describes the rank-n
oscillators.

**`oscillator_relations`.** Define
`standard_fermion_anticommutators` by
`{a_1_m, a_1_p} = 1` and
`{a_1_p, a_1_p} = {a_1_m, a_1_m} = 0`;
`bosonic_commutators` by `[b_i_m, b_j_p] = δ_ij` and zero like-sign
commutators; and `mixed_commutators` by `[b_i_±, a_1_±] = 0`.
Represent relation expressions as strings, following the existing B-schema.

**`central_elements` (top-level).** Define `kappa` with parity `1`, central
status, and nilpotency `kappa^2 = 0`; define `K` with parity `0`, central
status, and value `1`. Record both for schema completeness, but omit `K=1`
from the independent basis and PBW order. Include `kappa` in the PBW sequence
only when it is represented, as prescribed by I01.

**`basis` and `parity`.** Use the I01 order: optional `kappa`; odd positive
roots by increasing `k` (`E_eps1_del{k}_pp`, then `_pm`); odd negative roots
by increasing `k` (`_mp`, then `_mm`); `H_1` through `H_{n+1}`; positive even
roots (`E_2del{k}_p`, then pair labels `_pp`, `_pm`, each in increasing/lexical
index order); negative even roots (`E_2del{k}_m`, then pair labels `_mm`,
`_mp`). List the even generators in `basis.even`, the 4n odd generators in
`basis.odd`, and set parity to `0` for every even basis generator and `1` for
every odd one. `K` is not in either list.

**`generator_realization`.** Keep the B-schema `description`, `ordering`, and
`realizations` structure; order oscillator labels as `a_1_p, a_1_m`, followed
by `b_k_p, b_k_m` in increasing `k`. Use the finalized C(n+1) expressions:
`H_1 = a_1_p a_1_m + b_1_p b_1_m`;
`H_k = b_{k-1,p} b_{k-1,m} - b_{k,p} b_{k,m}` for `2 <= k <= n`;
`H_{n+1} = -b_{n,p} b_{n,m} - 1/2`;
`E_2del{k}_p/m = (b_k_p/m)^2`;
`E_del{i}_del{j}_XY = b_i_X b_j_Y` for `i<j`; and
`E_eps1_del{k}_pp/pm/mp/mm` is respectively
`a_1_p b_k_p`, `a_1_p b_k_m`, `a_1_m b_k_p`, `a_1_m b_k_m`.
Store each expression in the existing `standard_form` word/coefficient format
and include its `frappat_form` and parity. Use simple-generator normalization
factors only where required by the C(n+1) definition; they do not change
labels or root mapping.

**`structure_constants`.** Preserve the existing list format
`[{ "X": ..., "Y": ..., "Z": ..., "coeff": "...", "sign_rule": "graded" }]`.
Populate it with the nonzero graded brackets recomputed from the C(n+1)
oscillator realization and CAR/CCR above; do not reuse B(0,n) constants for
the changed odd sector.

**`metadata`.** Retain `generated_by`, `generation_date`, and `references`;
identify the C(n+1) structure-constant generator and cite the C(n+1)
definition alongside the existing general reference.

**Compatibility and file names.** Preserve Schema 1 v5.0's common key names,
word/coefficient representation, bracket-list representation, and
rank-specific evaluated dimensions. The C-family changes are isolated to
separate C files: fermion group/relation shape, 4n odd-root basis and
realizations, C dimensions, and the additional top-level central-elements
record; existing B-family files and interpretation remain unchanged.
Name each file `C_{n}_structure.json`, where `n` is bosonic rank
(`C(2)` → `C_1_structure.json`, `C(3)` → `C_2_structure.json`,
`C(4)` → `C_3_structure.json`).
