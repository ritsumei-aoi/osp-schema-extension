## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

#### Schema 1 proposal for human approval

The deliverable `docs/json_schema_specification.md` does not yet exist; after
approval, I will create it with the following complete Schema 1 field design.
It retains schema version `5.0`, the B(m,n) structure-constant record shape,
and the finalized Issue I01 basis labels and PBW ordering.

**Top-level keys**

```json
{
  "schema_version": "5.0",
  "algebra": {},
  "oscillator_generators": {},
  "oscillator_relations": {},
  "central_elements": {},
  "basis": {},
  "parity": {},
  "generator_realization": {},
  "structure_constants": [],
  "metadata": {}
}
```

`central_elements` is a new top-level key for C(n+1). `structure_constants`
continues to be a list of nonzero graded brackets with `X`, `Y`, `Z`, `coeff`,
and `sign_rule` fields as in the B(m,n) schema.

**Proposed field definitions**

- `algebra`: `family: "C"`, `m: 1`, `n: <bosonic rank>`,
  `cartan_type: "C(n+1)"`, `alternative_notation.osp: "osp(2|2n)"`,
  `alternative_notation.dimension_formula: "osp(2m|2n)"`, and `dimension`
  with `even: 2n^2+n+1`, `odd: 4n`, and `total: 2n^2+5n+1`. For example,
  at `n=2`, the dimensions are even 11, odd 8, total 19. The corresponding
  dimensions for `n=1,3` are `(4,4,8)` and `(22,12,34)`.
- `oscillator_generators`: a `fermions` object with `m: 1`,
  `count: 2`, `labels: ["a_1_p", "a_1_m"]`, `parity: 1`, and a description
  identifying the standard fermionic pair; plus a `bosons` object with
  `n: <bosonic rank>`, `count: 2n`, labels `b_1_p, b_1_m, ..., b_n_p, b_n_m`,
  and parity 0.
- `oscillator_relations`: `standard_fermion_anticommutators` describing
  `{a_1_m, a_1_p}=1`, `{a_1_p,a_1_p}={a_1_m,a_1_m}=0`;
  `bosonic_commutators` describing `[b_i^±,b_j^±]=0` and
  `[b_i^-,b_j^+]=δ_ij`; and `mixed_commutators` describing
  `[b_i^±,a_1^±]=0` in the undeformed algebra.
- `central_elements`: `kappa` with label `κ`, parity 1, central true, and
  nilpotent true; and `K` with label `K`, parity 0, central true, and
  `identification: "1"` / `independent_basis_element: false`. Neither is
  included in the finite-dimensional Lie-superalgebra basis or its PBW order.
- `basis`: `even` consists of `H_1,...,H_{n+1}`, all `E_2del{k}_p`,
  then all positive pair-root generators (`E_del{i}_del{j}_pp`,
  `E_del{i}_del{j}_pm`) in lexicographic `(i,j)` order, all
  `E_2del{k}_m`, then all negative pair-root generators
  (`E_del{i}_del{j}_mp`, `E_del{i}_del{j}_mm`) in lexicographic `(i,j)`
  order. `odd` consists, for increasing `k`, of
  `E_eps1_del{k}_pp, E_eps1_del{k}_pm, E_eps1_del{k}_mp,
  E_eps1_del{k}_mm`. `ordering_convention` states that PBW uses odd first
  in that order, then even in the order just specified (approved Issue I01
  Option A).
- `parity`: an explicit map for every basis label, 0 for every even label
  and 1 for every odd label; it excludes `K` and `κ`.
- `generator_realization`: `description`, an oscillator `ordering` of
  `a_1_p, a_1_m, b_1_p, b_1_m, ..., b_n_p, b_n_m`, and a `realizations`
  object with an entry for every basis generator. Store each as
  `standard_form` (a list of `{words: [...], coeff: "..."}` terms),
  `frappat_form`, and `parity`. Use
  `H_1 = a_1_p a_1_m + b_1_p b_1_m`,
  `H_k = b_{k-1}_p b_{k-1}_m - b_k_p b_k_m` for `2<=k<=n`,
  and `H_{n+1} = -b_n_p b_n_m - 1/2`;
  even root realizations follow the labels' signs, and the odd realizations
  are `a_1_p b_k_p`, `a_1_p b_k_m`, `a_1_m b_k_p`, and `a_1_m b_k_m`
  for suffixes `pp`, `pm`, `mp`, and `mm`, respectively.
- `structure_constants`: all nonzero brackets of the displayed basis,
  computed using the stated oscillator relations and recorded using the
  existing B(m,n) record shape, including `sign_rule: "graded"`.
- `metadata`: keep the B(m,n) fields `generated_by`, `generation_date`,
  and `references`, using a C-specific generator name and the C(n+1)
  references.

**Normalization point requiring approval:** `Cn1_definition.md` gives
`E_{2δ_n}=1/2 (b_n^+)^2` and `E_{-2δ_n}=1/2 (b_n^-)^2` in the simple-generator
section, but gives `E_{±2δ_k}=(b_k^±)^2` in its all-root section. I propose
using the all-root convention (coefficient 1) for every `k` in the schema,
avoiding a terminal-root special case. Please confirm or correct this choice
along with the field design.

**Compatibility and filenames:** keep the B(m,n) v5.0 field names, parity
encoding, and structure-constant record format unchanged for existing B
schemas. C files use the same schema version and shared field conventions,
with the C-specific fermion, central-elements, and basis definitions above.
Name each file `C_{n}_structure.json`, where `n` is the bosonic rank
(`C_1_structure.json` for C(2), `C_2_structure.json` for C(3), etc.).
