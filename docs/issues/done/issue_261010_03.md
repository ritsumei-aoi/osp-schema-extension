#### Verification and implementation proposal — 2026-10-10

Before opening this issue, I verified that `docs/json_schema_specification.md`
contains the I02 decisions: v5.0 C-family keys and dimensions, the top-level

**Proposed implementation.** Add `src/C_generators.py` with rank-driven
functions for the even/odd basis, parity, PBW order, oscillator realizations,
and Schema 1 payload. Compute brackets from the oscillator realizations rather
than copying B(0,n) constants: represent oscillator expressions as exact
rational linear combinations of words, normalize products using
`{a_1_m, a_1_p}=1` and `[b_i_m, b_j_p]=δ_ij`, and form `XY - (-1)^(p(X)p(Y))YX`.
Express each resulting bracket in the Cartan/root basis using exact rational
linear algebra; fail explicitly if a bracket does not lie in the span or has
an unexpected scalar remainder. Emit one record per nonzero bracket using a
consistent PBW-ordered pair convention and the specified `"graded"` sign
rule. A rank parameter should generate the three requested files with the
specification's metadata and generation date.

**Proposed tests.** For `n=1,2,3`, verify basis cardinalities and uniqueness,
even/odd parity assignments, PBW ordering, and the expected dimensions
`2n^2+n+1 | 4n`. Check closure of every graded bracket in the basis, graded
skew-symmetry, and the super-Jacobi identity; check the emitted payload's
required keys and realization labels against the specification. Use exact
rational coefficients throughout to avoid floating-point tolerances.
