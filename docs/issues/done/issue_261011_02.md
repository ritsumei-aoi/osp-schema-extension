## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Field 3: `oscillator_generators`

Replaces B(0,n)'s `supplementary_fermion` key with `fermions` (standard CAR pair):

```json
"oscillator_generators": {
  "fermions": {
    "m": 1,
    "labels": ["a_1_p", "a_1_m"],
    "parity": 1,
    "description": "Standard fermionic pair a_1^+, a_1^- satisfying CAR: {a_1^-, a_1^+} = 1"
  },
  "bosons": {
    "count": "<2*n>",
    "n": "<bosonic_rank>",
    "labels": ["b_1_p", "b_1_m", "b_2_p", "b_2_m", "..."],
    "description": "Bosonic oscillators b_k^+, b_k^- for k=1,...,n with CCR: [b_k^-, b_l^+] = delta_{kl}"
  }
}
```

Example for n=2 (C(3)):
```json
"oscillator_generators": {
  "fermions": {
    "m": 1,
    "labels": ["a_1_p", "a_1_m"],
    "parity": 1,
    "description": "Standard fermionic pair a_1^+, a_1^- satisfying CAR: {a_1^-, a_1^+} = 1"
  },
  "bosons": {
    "count": 4,
    "n": 2,
    "labels": ["b_1_p", "b_1_m", "b_2_p", "b_2_m"],
    "description": "Bosonic oscillators b_k^+, b_k^- for k=1,2 with CCR: [b_k^-, b_l^+] = delta_{kl}"
  }
}
```

**Compatibility note**: B(0,n) uses key `supplementary_fermion` (single `a_0`). C(n+1) uses key `fermions` (pair `a_1_p`, `a_1_m`). Parsers should branch on `oscillator_generators.fermions` vs `oscillator_generators.supplementary_fermion` to distinguish the two families.

### Field 4: `oscillator_relations`

Replaces B(0,n)'s `supplementary_fermion_relation` with `standard_fermion_anticommutators`:

```json
"oscillator_relations": {
  "standard_fermion_anticommutators": {
    "description": "Canonical anticommutation relations (CAR) for the standard fermionic pair",
    "relations": {
      "self_anticommutators": "{a_1^+, a_1^+} = 0, {a_1^-, a_1^-} = 0",
      "conjugate_pair": "{a_1^-, a_1^+} = 1"
    }
  },
  "bosonic_commutators": {
    "description": "Canonical commutation relations (CCR) for bosonic oscillators",
    "relations": {
      "same_type": "[b_i^pm, b_j^pm] = 0 for all i, j",
      "conjugate_pair": "[b_i^-, b_j^+] = delta_{ij}"
    }
  },
  "mixed_commutators": {
    "boson_fermion": "[b_i^pm, a_1^pm] = 0  (bosons and fermions commute)"
  }
}
```

**Compatibility note**: B(0,n) has `supplementary_fermion_relation: "a_0 * a_0 = 1/2"`. C(n+1) has `standard_fermion_anticommutators` with `{a_1^-, a_1^+} = 1`. The structural difference is that a₀ satisfies a non-standard relation while a₁± satisfy the standard CAR.

### Field 5: `central_elements` (top-level key)

This is a **new top-level key** absent from B(0,n) schema (B(0,n) includes K only as a schema-completeness note, not a top-level key). For C(n+1):

```json
"central_elements": {
  "K": {
    "label": "K",
    "parity": 0,
    "description": "Even central identity element; identified with scalar 1 in all current applications. Excluded from PBW basis. (Bakalov-Sullivan arXiv:1612.09400)"
  },
  "kappa": {
    "label": "kappa",
    "parity": 1,
    "nilpotency": "kappa^2 = 0",
    "pbw_position": "smallest (precedes all basis elements)",
    "description": "Odd nilpotent central extension element. Deformation: a_1^2 maps to kappa * (sum of deformation parameters gb_{a_1, b_k^pm} * b_k^pm)."
  }
}
```

**Rationale**: κ is odd (parity 1), nilpotent (κ²=0), and is the formal symbol of the inhomogeneous extension. K is even (parity 0) and serves as a bookkeeping element for the central identity. Both are referenced by the γ-structure in Schema 2.

### File Naming Convention

Per the mandatory unified rule:

| JSON file | Algebra | n (bosonic rank) |
|---|---|---|
| `C_1_structure.json` | C(2) = osp(2\|2) | 1 |
| `C_2_structure.json` | C(3) = osp(2\|4) | 2 |
| `C_3_structure.json` | C(4) = osp(2\|6) | 3 |

Pattern: `C_{n}_{layer}.json` where `n` is the bosonic rank and `layer` is one of `structure`, `gamma`, `evaluated_<gb>`, `coboundary_<gb>`.
