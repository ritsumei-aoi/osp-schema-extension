## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

#### Approved Schema 1 field decisions

The proposal keeps the v5.0 Schema 1 object shapes for fields shared with
B(m,n), adds the required top-level `central_elements`, and substitutes the
C(n+1) oscillator, basis, parity, and realization data. Each concrete
`C_n_structure.json` instance uses its bosonic rank `n`; formulas below are
stored as strings, while `dimension` also contains the evaluated integers.

**Top-level keys**

Retain `"schema_version": "5.0"` and the v5.0 keys `algebra`,
`oscillator_generators`, `oscillator_relations`, `basis`, `parity`,
`generator_realization`, `structure_constants`, and `metadata`. Add
`central_elements` as a top-level key. Thus a complete Schema 1 document has:

```json
{
  "schema_version": "5.0",
  "algebra": {},
  "oscillator_generators": {},
  "oscillator_relations": {},
  "central_elements": {},
  "basis": {},
  "parity": {},
  "generator_realization": {},
  "structure_constants": [],
  "metadata": {}
}
```

**`algebra`**

For each instance, use `family: "C"`, `m: 1`, bosonic rank `n`, concrete
`cartan_type: "C(n+1)"` with the expression evaluated (for example
`"C(3)"` when `n=2`), and `osp: "osp(2|2n)"` with `n` evaluated. Keep numeric
dimension values and record all three formulas:

```json
{
  "family": "C",
  "m": 1,
  "n": 2,
  "cartan_type": "C(3)",
  "alternative_notation": {
    "osp": "osp(2|4)",
    "dimension_formula": "osp(2m|2n), with m=1"
  },
  "dimension": {
    "total": 19,
    "even": 11,
    "odd": 8,
    "formula": {
      "even": "2n^2+n+1",
      "odd": "4n",
      "total": "2n^2+5n+1"
    }
  }
}
```

For `n=1,2,3`, the respective `(even, odd, total)` values are `(4,4,8)`,
`(11,8,19)`, and `(22,12,34)`.

**`oscillator_generators`**

Replace B(0,n)'s `supplementary_fermion` with the mandatory `fermions` key;
retain a `bosons` key. The labels are ordered as shown:

```json
{
  "fermions": {
    "m": 1,
    "count": 2,
    "labels": ["a_1_p", "a_1_m"],
    "parity": 1,
    "description": "One standard fermionic pair a_1^+, a_1^-."
  },
  "bosons": {
    "n": 2,
    "count": 4,
    "labels": ["b_1_p", "b_1_m", "b_2_p", "b_2_m"],
    "parity": 0,
    "description": "Bosonic oscillators b_k^± for k=1,...,n."
  }
}
```

For arbitrary `n`, `bosons.count` is `2n` and its labels enumerate
`b_1_p`, `b_1_m`, ..., `b_n_p`, `b_n_m`.

**`oscillator_relations`**

Use a standard fermionic CAR relation, canonical bosonic CCR, and undeformed
zero mixed commutators:

```json
{
  "standard_fermion_anticommutators": {
    "description": "Canonical anticommutation relations for a_1^±.",
    "relations": {
      "conjugate_pair": "{a_1_m, a_1_p} = {a_1_p, a_1_m} = 1",
      "same_type": "{a_1_p, a_1_p} = {a_1_m, a_1_m} = 0"
    }
  },
  "bosonic_commutators": {
    "description": "Canonical commutation relations for b_k^±.",
    "relations": {
      "same_type": "[b_i^+, b_j^+] = [b_i^-, b_j^-] = 0 for all i,j",
      "conjugate_pair": "[b_i^-, b_j^+] = δ_ij"
    }
  },
  "mixed_commutators": {
    "boson_fermion": "[b_j^s, a_1^σ] = 0 for all j and s,σ in {+,-}"
  }
}
```

The `gb`-deformed exchange relations belong to Schema 2, not these undeformed
Schema 1 relations.

**Top-level `central_elements`**

Record both formal central symbols, but do not add either as an ordinary
generator in the C(n+1) basis. `K` is the even scalar identity; `kappa` is
the odd nilpotent central symbol for the deformation extension:

```json
{
  "kappa": {
    "label": "κ",
    "parity": 1,
    "central": true,
    "nilpotent": true,
    "relation": "κ^2 = 0",
    "description": "Odd central symbol used by the inhomogeneous extension."
  },
  "K": {
    "label": "K",
    "parity": 0,
    "central": true,
    "identified_with": "1",
    "independent_basis_element": false,
    "description": "Even central identity; excluded from the basis."
  }
}
```

For PBW documentation, retain the approved Issue I01 convention:
`κ < [odd basis] < [even basis]`; `K=1` is excluded. The `kappa` symbol is
not included in the dimensions of `g`.

**`basis`**

Build the arrays using the approved Issue I01 labels and order. The even array
contains `H_1` through `H_{n+1}`, then positive root families
`E_2del{k}_p`, `E_del{i}_del{j}_pp`, `E_del{i}_del{j}_pm`, then negative
families `E_2del{k}_m`, `E_del{i}_del{j}_mm`, `E_del{i}_del{j}_mp`.
Use ascending `k` and lexicographic pairs `(i,j)` with `i<j`. The odd array
contains, for each ascending `k`, `E_eps1_del{k}_pp`, `..._pm`, `..._mp`,
`..._mm`. Include the ordering convention explicitly:

```json
{
  "even": ["H_1", "...", "H_{n+1}", "... all even root labels in the order above ..."],
  "odd": ["... odd labels in the order above ..."],
  "ordering_convention": "PBW: κ < [odd: k ascending, pp, pm, mp, mm] < [even: H; positive roots; negative roots] (K=1 is excluded)"
}
```

The ellipses here specify rank-generated arrays, not literal basis entries;
each output schema must expand them into its full concrete string arrays.

**`parity`**

Use a JSON object keyed by every generator in `basis`: assign `0` to all
`H_i`, `E_2del{k}_p/m`, and `E_del{i}_del{j}_pp/pm/mp/mm`; assign `1` to all
`E_eps1_del{k}_pp/pm/mp/mm`. Central-element parity remains in
`central_elements`, not this basis parity map.

**`generator_realization`**

Retain the v5.0 object shape: `description`, `ordering`, and `realizations`.
Set oscillator `ordering` to `a_1_p, a_1_m, b_1_p, b_1_m, ..., b_n_p, b_n_m`.
Provide a realization for every generator in `basis`, each with
`standard_form` (list of `{ "words": [...], "coeff": "..." }` terms),
`frappat_form`, and `parity`. Use the finalized Issue I01 realizations:

- `H_1`: `a_1_p a_1_m + b_1_p b_1_m`.
- `H_k` for `2<=k<=n`: `b_{k-1}_p b_{k-1}_m - b_k_p b_k_m`.
- `H_{n+1}`: `-b_n_p b_n_m - 1/2`.
- Even root labels map to the corresponding oscillator products defined in
  `handover/notation.md`, with coefficient `1` (including
  `E_2del{k}_p/m = (b_k^±)^2`).
- `E_eps1_del{k}_pp/pm/mp/mm` map respectively to
  `a_1_p b_k_p`, `a_1_p b_k_m`, `a_1_m b_k_p`, `a_1_m b_k_m`, coefficient `1`.

Represent constants as empty-word terms, e.g. `{"words": [], "coeff": "-1/2"}`.
Do not include `kappa` or `K` realizations in this basis map.

**`structure_constants` and `metadata`**

Keep the v5.0 structure-constant list shape unchanged. Every nonzero
undeformed graded bracket has `{ "X": "<basis label>", "Y": "<basis label>",
"Z": "<basis label>", "coeff": "<rational>", "sign_rule": "graded" }`.
The entries must be regenerated using the C(n+1) CAR/CCR and C(n+1)
realizations; do not copy B(0,n) coefficients. This field describes the
undeformed algebra only.

Keep the v5.0 metadata shape, using a C-specific generator name and the
generation date, e.g. `"generated_by": "build_C_structure_constants.py"`,
`"generation_date": "YYYY-MM-DD"`, plus the Frappat et al. and
Bakalov–Sullivan references.

**Compatibility and filenames**

The schema version and shapes of the shared top-level fields remain v5.0
compatible. Differences from B(m,n) are the `family`/`m`/dimension data,
the replacement `fermions` and CAR relations, C(n+1) basis and parity,
realizations and recomputed constants, plus the new top-level
`central_elements`. Name each instance `C_{n}_structure.json`, where `n` is
the bosonic rank: `C_1_structure.json` for C(2), `C_2_structure.json` for
C(3), and `C_3_structure.json` for C(4).

metadata, compatibility, and filename proposals on 2026-10-11. The finalized
