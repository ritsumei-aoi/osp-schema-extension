## Proposal for C(n+1) basis, PBW ordering, and generator labels

### 1. Fixed generator-label design

I propose keeping the existing B(0,n) even-generator naming pattern and extending it to the C(n+1) odd roots as follows.

- Oscillator labels:
  - fermions: `a_1_p`, `a_1_m`
  - bosons: `b_k_p`, `b_k_m` for `k = 1, ..., n`
- Cartan labels:
  - `H_1, ..., H_{n+1}`
- Even root-generator labels:
  - `E_2del{k}_p`, `E_2del{k}_m`
  - `E_del{i}_del{j}_pp`, `E_del{i}_del{j}_mm`, `E_del{i}_del{j}_pm`, `E_del{i}_del{j}_mp` for `i < j`
- Odd root-generator labels:
  - `E_eps1_del{k}_pp` for `\varepsilon + \delta_k`
  - `E_eps1_del{k}_pm` for `\varepsilon - \delta_k`
  - `E_eps1_del{k}_mp` for `-\varepsilon + \delta_k`
  - `E_eps1_del{k}_mm` for `-\varepsilon - \delta_k`

This label system is consistent with the current schema style:
the first sign records the fermionic oscillator (`a_1_p` / `a_1_m`),
and the second sign records the bosonic oscillator (`b_k_p` / `b_k_m`).

### 3. PBW ordering options requiring human approval

I see two clean options.

#### Option A — compatibility-first (recommended)

Use the same large-block style as the current B(0,n) schema material:

`kappa < [odd block] < [even block]`

with the odd and even blocks ordered by generator-family labels.

- Odd block:
  - `E_eps1_del1_pp, ..., E_eps1_deln_pp,`
  - `E_eps1_del1_pm, ..., E_eps1_deln_pm,`
  - `E_eps1_del1_mp, ..., E_eps1_deln_mp,`
  - `E_eps1_del1_mm, ..., E_eps1_deln_mm`
- Even block:
  - `H_1, ..., H_{n+1},`
  - `E_2del1_p, ..., E_2deln_p,`
  - `E_del{i}_del{j}_pp` in lexicographic `(i,j)` order,
  - `E_del{i}_del{j}_pm` in lexicographic `(i,j)` order,
  - `E_2del1_m, ..., E_2deln_m,`
  - `E_del{i}_del{j}_mm` in lexicographic `(i,j)` order,
  - `E_del{i}_del{j}_mp` in lexicographic `(i,j)` order

Why I recommend Option A:

1. It preserves the repository's existing schema-label logic from B(0,n).
2. Each label family stays contiguous, which is convenient for JSON generation and later diff review.
3. It aligns with the already-written provisional wording in `docs/math/Cn1_definition.md`, which currently assumes a fermionic-first convention.

#### Option B — root-theoretic / simple-root-first

Still keep the major block split

`kappa < [odd block] < [even block]`,

but order families so positive/simple-root-style generators appear first.

- Odd block:
  - `E_eps1_del1_pm, ..., E_eps1_deln_pm,`
  - `E_eps1_del1_pp, ..., E_eps1_deln_pp,`
  - `E_eps1_del1_mp, ..., E_eps1_deln_mp,`
  - `E_eps1_del1_mm, ..., E_eps1_deln_mm`
- Even block:
  - `H_1, ..., H_{n+1},`
  - positive even roots first:
    - `E_del{i}_del{j}_pm`,
    - `E_2del{k}_p`,
    - `E_del{i}_del{j}_pp`,
  - then negative even roots:
    - `E_del{i}_del{j}_mp`,
    - `E_2del{k}_m`,
    - `E_del{i}_del{j}_mm`

Why Option B is plausible:

1. `E_{eps1_del1_pm}` corresponds to the simple odd root `\varepsilon - \delta_1`, so this is closer to a simple-root-first reading.
2. Positive roots precede negative roots more transparently.
3. It is mathematically cleaner if the main goal is root-theoretic readability rather than schema continuity.

### 4. Recommendation

I recommend **Option A**.

It is the safer repository-level convention because it minimizes discontinuity with the existing B(0,n) schema naming/order style, keeps generator families contiguous, and makes later automation simpler.
