#### Proposed gamma computation and Schema 2 shape

The repository describes the four-layer filenames but has no existing Schema 2
field specification or gamma JSON to extend. I propose `data/C_{n}_gamma.json`
for each bosonic rank \(n\), with the same `"schema_version": "5.0"` and
`algebra` object as its Schema 1 companion. Put the deformation data under a
top-level `inhomogeneous_deformation` object:

```json
{
  "schema_version": "5.0",
  "algebra": {},
  "inhomogeneous_deformation": {
    "gb_matrix": {
      "row_labels": ["a_1_p", "a_1_m"],
      "column_labels": ["b_1_p", "b_1_m"],
      "entries": [
        ["gb_a1_p_b1_p", "gb_a1_p_b1_m"],
        ["gb_a1_m_b1_p", "gb_a1_m_b1_m"]
      ]
    },
    "deformed_relations": [],
    "gamma_structure": []
  },
  "metadata": {}
}
```

For general \(n\), the matrix has the two fermion rows in the order
`a_1_p`, `a_1_m`, and \(2n\) boson columns in the order
`b_1_p`, `b_1_m`, ..., `b_n_p`, `b_n_m`. This gives exactly \(4n\) independent
parameters. Each nonzero gamma entry would use the Schema 1 bracket record
shape (`X`, `Y`, `Z`, `coeff`, `sign_rule`), with `coeff` a canonical exact
linear expression in the `gb_matrix` symbols and `sign_rule` equal to
`"graded"`. Store only nonzero coefficients and order records deterministically
by the Schema 1 PBW basis.

The proposed computation is to replace each mixed oscillator relation by its
approved deformed value, compute each generator bracket with the same exact
normal-ordering machinery as Schema 1, subtract the undeformed bracket, and
extract the coefficient of \(\kappa\). Expand the result in the Schema 1
basis; reject any nonzero residual outside its span or any term not linear in
the deformation parameters. Verify that setting every `gb` to zero recovers
Schema 1 and that the gamma bracket obeys the selected graded sign convention.

#### Sign convention choices for approval

**Option A (recommended: literal convention from
`C_inhomogeneous_definition.md`):** use
\[
[b_j^s,a_1^\sigma]_\gamma-[b_j^s,a_1^\sigma]_0
=-\mathrm{gb}_{\sigma,j,s}\,\kappa.
\]
The reversed ordered pair then has the opposite correction by graded
anti-symmetry. Define the stored gamma coefficient by
\([X,Y]_\gamma=[X,Y]_0+\kappa\,\gamma(X,Y)\), with \(\kappa\) on the left.
The parameter matrix entries are the \(\mathrm{gb}_{\sigma,j,s}\) themselves.

**Option B (positive relation-coefficient convention):** define each stored
matrix entry as the negative of the reference parameter,
\(\widehat{\mathrm{gb}}_{\sigma,j,s}=-\mathrm{gb}_{\sigma,j,s}\). Then store
the mixed relation correction as
\([b_j^s,a_1^\sigma]_\gamma-[b_j^s,a_1^\sigma]_0
=+\widehat{\mathrm{gb}}_{\sigma,j,s}\,\kappa\). This is a reparameterization
of Option A; the mapping back to the reference parameters must be recorded in
the JSON.

#### Mathematical clarification required

`C_inhomogeneous_definition.md` assigns parity 1 to both \(\mathrm{gb}\) and
\(\kappa\), but its mixed relation has an even right-hand side

their bracket is odd. This relation is not parity-homogeneous with both

Please confirm whether the intended resolution is to treat the `gb`
parameters as even scalars (recommended to make the displayed mixed relation

parity assignment. Please also select Option A or Option B for the serialized
sign convention. These decisions affect the gamma parity checks and all
generated coefficients.

\mathrm{gb}_{a_1^+,b_1^+}(H_1+K)
