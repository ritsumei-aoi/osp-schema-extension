### Response

**Script**: `src/verify_C_structure.py`. It reads only the three Schema 1 JSON files (not the engine), builds the full bracket table from the stored i≤j entries using the super-skew rule, and checks format, anti-symmetry, and the super-Jacobi identity for every ordered triple.

**Result (run output, `python3 src/verify_C_structure.py`, exit code 0)**

All ordered triples were checked: $8^3$, $19^3$, $34^3$ for $n=1,2,3$.

**Checks performed**

- Parity: every entry has $p(Z)\equiv p(X)+p(Y)$ mod 2.
- Index order: no stored entry has index(X) > index(Y); the reverse order is derived by the super-skew rule.
- Closure: no `K` (constant) residual appears in any entry.
- Even self-brackets: $[X,X]=0$ for every even $X$.
- Super-Jacobi: $[X,[Y,Z]]=[[X,Y],Z]+(-1)^{p(X)p(Y)}[Y,[X,Z]]$.

**Sensitivity check**: changing one coefficient in the $n=1$ data (the $[E_{\varepsilon+\delta},E_{-\varepsilon-\delta}]\to H_1$ term, $-1\to-2$) gives 30 failing Jacobi triples out of 512. So the check is not vacuous.

**Failures during development (fixed in the verifier, not in the data)**: The first run reported 21 / 91 / 201 format failures and many Jacobi failures. (1) The verifier assembled the basis as even+odd, but I01 fixed the PBW order as odd-first, so the i≤j half was misidentified. (2) The duplicate check flagged a pair (X,Y) that legitimately has several Z entries. Both were fixed by matching the I01 order and checking duplicates per (X,Y,Z). The data was not changed.

**Consequence**: Schema 1 is consistent. The bracket is a Lie superalgebra for $n=1,2,3$, so Schema 2 can be built on it.
