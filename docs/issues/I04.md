### Response

**Implementation**: `src/verify_C_structure.py` loads `data/C_{1,2,3}_structure.json`, checks anti-symmetry `[X,Y} = -(-1)^{p(X)p(Y)}[Y,X}` for **all** ordered pairs and the super Jacobi identity `[X,[Y,Z}} = [[X,Y},Z} + (-1)^{p(X)p(Y)}[Y,[X,Z}}` for **all** N³ ordered triples (exact `Fraction` arithmetic). Tests are in `tests/test_verify_C_structure.py` (including a corruption test showing the checker detects a perturbed constant).

**Failure found and root cause (first run)**: the first run reported `C_1 PASS`, but `C_2: jacobi_fail=462`, `C_3: jacobi_fail=1686` (anti-symmetry passed everywhere). Root cause: a bug in my own `Decomposer.decompose` (I03 code). When converting the Weyl-symmetric diagonal elements h_k back to Cartan generators I used h_k = −(H_{k+1}+…+H_{n+1}). The correct inversion of H_k = h_{k-1} − h_k, H_{n+1} = −h_n is h_k = H_{k+1}+…+H_n − H_{n+1}. The two agree for n=1 (hence C_1 passed) and differ for n ≥ 2, so the I03-committed data for n=2,3 had wrong Cartan coefficients. Fix: corrected the inversion, regenerated all three `data/C_{n}_structure.json` (this I04 commit contains the corrected data), and added the regression test `test_decomposer_roundtrip` (decomposing each generator's realization returns exactly that generator). The I03 tests did not catch it because they only compared the JSON with the same generator code.
