## Context & Background
C(n+1) = osp(2|2n) uses a standard fermionic pair (a_1_p, a_1_m) instead of
B(0,n)'s supplementary fermion a_0. This changes the basis structure, PBW
ordering, and oscillator relations throughout the entire schema.

The existing B(0,n) implementation is available for reference at:
https://github.com/ritsumei-aoi/osp-triviality

For C(n+1) root structure, refer to:
Frappat et al., "Dictionary on Lie Algebras and Superalgebras", arXiv:hep-th/9607161

### Response

**Summary.** Finalized the C(n+1) = osp(2|2n) basis, generator labels, and PBW ordering;
wrote all of it into `handover/notation.md`.

**Basis design.** Dimensions follow even $=2n^2+n+1$, odd $=4n$, total $=2n^2+5n+1$, giving
(even, odd, total) = (4,4,8) for C(2), (11,8,19) for C(3), (22,12,34) for C(4). The even sector
splits as $(n+1)$ Cartan generators $H_1,\dots,H_{n+1}$ plus $2n^2$ sp(2n) root vectors
($2n$ of type $E_{\pm 2\delta_k}$ and $2n(n-1)$ of type $E_{\pm(\delta_i\pm\delta_j)}$); the odd
sector is the $4n$ generators $E_{\pm\varepsilon\pm\delta_k}$. Explicit ordered lists for C(2),
C(3), C(4) are in notation.md §4.

**Generator labels (§3).** Kept the $B(0,n)$ `E_...` naming for the even sp(2n) block
(`E_2del{k}_p/m`, `E_del{i}_del{j}_pp/mm/pm/mp`) and the Cartan `H_i`. Introduced
`E_eps1_del{k}_{s1}{s2}` for the odd roots, where `s1` is the sign of $\varepsilon$ and `s2` the
sign of $\delta_k$. Realizations: $E_{\varepsilon+\delta_k}=a_1^+b_k^+$ (`_pp`),
$a_1^+b_k^-$ (`_pm`), $a_1^-b_k^+$ (`_mp`), $a_1^-b_k^-$ (`_mm`). Cartan generators taken exactly
from Frappat (so $H_{n+1}$ carries the $-\tfrac12$ normal-ordering constant).

**PBW ordering — options considered.**
- *Option A (chosen):* `κ < [odd] < [even]`, matching the existing $B(0,n)$ v5.0 schema.
- *Option B (rejected):* order by root height, interleaving even/odd generators.

*Reason for A:* backward compatibility with the $B(0,n)$ base schema and its tooling, and it keeps
the odd central $\kappa$ adjacent to the odd generators used by the deformation. The
structure-constant engine built in I03 is basis-order agnostic (it decomposes each bracket into the
declared basis), so Option B would add churn with no computational benefit.

**Decision on $\kappa$ parity.** The math docs are mildly inconsistent ($B(0,n)$ schema note says
"parity 0 in the schema", while $C$ inhomogeneous says $p(\kappa)=1$). I adopt $\kappa$ **parity 1**
in `central_elements`, per the I02 mandatory unified rule and the correct odd parity used in the
deformation. Recorded in notation.md §6.

**Deliverable:** `handover/notation.md` updated (§1–§6). All three completion criteria met.
