## Context & Background
C(n+1) = osp(2|2n) uses a standard fermionic pair (a_1_p, a_1_m) instead of
B(0,n)'s supplementary fermion a_0. This changes the basis structure, PBW
ordering, and oscillator relations throughout the entire schema.

The existing B(0,n) implementation is available for reference at:
https://github.com/ritsumei-aoi/osp-triviality

For C(n+1) root structure, refer to:
Frappat et al., "Dictionary on Lie Algebras and Superalgebras", arXiv:hep-th/9607161

3. Design oscillator generator labels consistent with `handover/notation.md`.

### Response

**Date**: 2026-10-09. All work is based on `docs/math/*.md` only (no external access; the GitHub and arXiv links in the Context were not opened).

#### 1. Basis lists (Requirement 1)

Root system from `Cn1_definition.md`: $\Delta_{\bar0} = \{\pm2\delta_k, \pm(\delta_i\pm\delta_j)\}$, $\Delta_{\bar1} = \{\pm\varepsilon\pm\delta_k\}$, even subalgebra $\mathfrak{so}(2)\times\mathfrak{sp}(2n)$ with $n+1$ Cartan generators. Counting: even $= (n+1) + 2n + 4\binom n2 = 2n^2+n+1$, odd $= 4n$.

| $n$ | algebra | even | odd | total |
|---|---|---|---|---|
| 1 | C(2) | 4 | 4 | 8 |
| 2 | C(3) | 11 | 8 | 19 |
| 3 | C(4) | 22 | 12 | 34 |

The explicit lists for C(2), C(3), C(4) are written out in `handover/notation.md` §4 and match these counts. Cartan generators are Frappat's $H_1 = a_1^+a_1^- + b_1^+b_1^-$, $H_k = b_{k-1}^+b_{k-1}^- - b_k^+b_k^-$, $H_{n+1} = -b_n^+b_n^- - \tfrac12$ (constant kept, since $[(b_n^+)^2,(b_n^-)^2] = -4(b_n^+b_n^-+\tfrac12)$ and the span must close without using $K$). I verified by hand that $\{H_1,\dots,H_{n+1}\}$ is a basis of the span of the symmetrized number operators $J = a_1^+a_1^- - \tfrac12$, $\tilde N_k = b_k^+b_k^- + \tfrac12$ (triangular change of basis), so the $\mathfrak{so}(2)$ generator is $J = H_1 - H_2 - \cdots - H_n + H_{n+1}$.

**Decision (normalisation)**: the basis uses $E_{\pm2\delta_k} = (b_k^\pm)^2$ for all $k$ (as in the B(0,n) schema), not the $\tfrac12(b_n^\pm)^2$ of the simple-root normalisation in `Cn1_definition.md` §2. Reason: uniformity across $k$ and compatibility with `B0n_definition.md`; it only rescales structure constants.

#### 2. PBW ordering (Requirement 2) — options considered

* **Option A (chosen)**: `kappa < [odd] < [even]`, odd block ordered sign-major ($\varepsilon$-sign, then $\delta$-sign, then $k$), even block laid out exactly as B(0,n) v5.0 with $n+1$ Cartans first.
* **Option B**: `kappa < [even] < [odd]` (even first, mirroring the $\mathfrak g_{\bar0}\oplus\mathfrak g_{\bar1}$ decomposition order).
* **Option C**: root-height ordering (Cartans, then positive roots by height, then negative roots), mixing parities.

Chosen: **A**. Reasons: (i) it is the direct extension of the B(0,n) convention `κ < [odd] < [even]`, so Schema 1 consumers written for B(0,n) keep working (backward compatibility is an explicit I02 goal); (ii) keeping the odd block contiguous and first is convenient for the odd map $f$ of I07 (parity blocks are contiguous index ranges); (iii) Option C would break the `basis.even`/`basis.odd` split of the schema. Within the odd block the $\varepsilon$-sign is the outer key because $\pm\varepsilon$ fixes which fermion ($a_1^\pm$) appears, so each half of the odd block is exactly the image of $B(0,n)$'s $E_{\pm\delta_k}$ under $a_0 \mapsto a_1^\pm$.

#### 3. Generator labels (Requirement 3)

Odd generators: `E_eps1_del{k}_{σ}{s}` $= a_1^\sigma b_k^s$ (first letter = $\varepsilon$ sign, second = $\delta_k$ sign), e.g. `E_eps1_del2_pm` $= a_1^+ b_2^-$. Even generators keep the B(0,n) labels; Cartans are `H_1 … H_{n+1}`. Oscillator labels: `a_1_p`, `a_1_m`, `b_{k}_p`, `b_{k}_m`, plus `kappa`, `K`. Oscillator normal-ordering: `kappa < a_1_p < a_1_m < b_1_p < b_1_m < …`. Deformation parameters: `gb_a1{σ}_b{k}{s}`.

#### 4. Ambiguities recorded

* `Cn1_definition.md` §2 gives $E_{\pm2\delta_n} = \tfrac12 (b_n^\pm)^2$ for the simple roots but $(b_k^\pm)^2$ in the "all root generators" table. Adopted: $(b_k^\pm)^2$ (see Decision above).
* Parity of $\kappa$: `B0n_definition.md` lists $\kappa$ with parity 0 in the JSON while the mathematics says $p(\kappa)=1$. For C(n+1) the I02 mandatory rule fixes `kappa` parity 1, which is adopted everywhere (documented in notation.md §1).
