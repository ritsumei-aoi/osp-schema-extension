## Context & Background
C(n+1) = osp(2|2n) uses a standard fermionic pair (a_1_p, a_1_m) instead of
B(0,n)'s supplementary fermion a_0. This changes the basis structure, PBW
ordering, and oscillator relations throughout the entire schema.

The existing B(0,n) implementation is available for reference at:
https://github.com/ritsumei-aoi/osp-triviality

For C(n+1) root structure, refer to:
Frappat et al., "Dictionary on Lie Algebras and Superalgebras", arXiv:hep-th/9607161

### Response

**Date**: 2026-10-10 — **Status**: closed (all criteria met)

#### 1. Basis design

Even/odd basis lists for C(2), C(3), C(4) are fully enumerated in
`handover/notation.md` §4. Counts verified against the dimension formulas
even = 2n²+n+1, odd = 4n: C(2): 4|4 (total 8), C(3): 11|8 (total 19),
C(4): 22|12 (total 34) — matching `docs/math/Cn1_definition.md` §1.

Design decisions:
- **Cartan sector**: `H_eps = a_1^+ a_1^- − 1/2` (so(2) factor) plus
  `H_k = b_k^+ b_k^- + 1/2` (k=1..n, sp(2n) Cartan). The constant shifts are
  chosen deliberately so that all brackets close on the basis without an
  identity element, e.g. `[E_2del_k_m, E_2del_k_p] = 4H_k` and
  `{E_eps_del_k_pp, E_eps_del_k_mm} = H_k − H_eps`,
  `{E_eps_del_k_pm, E_eps_del_k_mp} = H_k + H_eps`
  (hand-checked via CAR/CCR; mechanically re-verified in I03/I04).
  Note this differs from the simple-generator normalization in
  `Cn1_definition.md` §2 (which uses `H_1 = a_1^+a_1^- + b_1^+b_1^-` etc.);
  those simple-root Cartans are integer linear combinations of our basis
  (e.g. Frappat `H_1` = `H_eps + H_1(ours)` up to the constant), so no
  information is lost. A diagonal "one Cartan per oscillator" basis is far
  better suited to a schema that must scale uniformly in n.
- **Odd generators**: `E_eps_del{k}_{σs} = a_1^σ b_k^s`, first sign = ε-sign,
  second = δ_k-sign. This replaces B(0,n)'s 2n generators `E_del{k}_p/m`
  with 4n generators, as required.
- **Even root vectors**: identical labels and realizations as B(0,n)
  (`E_2del{k}_±`, `E_del{i}_del{j}_{pp,mm,pm,mp}`), preserving backward
  compatibility of the sp(2n) sector.

#### 2. PBW ordering — options considered

- **Option A (chosen)**: `κ < [odd] < [even]` — identical to the B(0,n) v5.0
  convention (`B0n_schema_v5.md`, basis section).
- **Option B**: `κ < [even] < [odd]` — "Cartan–even first" ordering, common in
  textbook PBW statements.
- **Option C**: root-height ordering interleaving even/odd by ε-weight
  (a_1^+-block < even < a_1^--block), which makes ε-charge grading explicit.

**Decision: Option A.** Rationale: (i) maximal consistency with the existing
B(0,n) tooling and schema v5.0, minimizing downstream changes in Schemas 2–4;
(ii) odd-first ordering keeps all κ-adjacent (parity-1) objects contiguous,
which simplifies the coboundary bookkeeping in I07; (iii) Option C adds no
computational benefit at quadratic oscillator degree. Within the odd block,
ordering is (ε-sign, δ-sign, k): a_1^+-terms before a_1^−-terms, matching the
B(0,n) pattern of grouping raising before lowering.
