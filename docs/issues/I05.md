### Response

Implemented `src/C_gamma.py` and generated `data/C_1_gamma.json`,
`data/C_2_gamma.json`, and `data/C_3_gamma.json`. Each file includes a 2 x 2n
`gb_matrix`, all literal oscillator exchange relations, and first-order
`gamma_coefficients` computed by exact normal ordering. Components are
expressed in the matching Schema 1 basis, with `K` included where a scalar
component is required.

Recorded and resolved a mathematical ambiguity rather than halting: the source
assigns odd parity to both `gb` and `kappa`, but their product is used as the
right-hand side of a mixed commutator between an even and odd oscillator.
Those parity statements are inconsistent. I followed the explicitly given
exchange relation literally, treating `gb*kappa` as a formal first-order
coefficient and not asserting parity consistency. This choice is documented
in the Schema 2 specification and generated data.

Consistency checks confirm that each gamma schema references its matching
Schema 1 rank, contains 4n unique parameters with every parameter represented,
and uses only Schema 1 generators or the declared central identity `K`.
Generated counts: 4 parameters / 60 terms for n=1, 8 / 334 for n=2, and
12 / 932 for n=3. Verification output: `python -m pytest -q` -> `7 passed in
2.41s`; the Schema 1 verifier also passed all pair and Jacobi checks.

During generation, the environment intermittently lacked the declared SymPy
dependency. To avoid any package install or network access, replaced the
generator's coordinate solver with exact `Fraction` Gaussian elimination;
the Schema 1 and Schema 2 regression tests pass with that implementation.
Completion criteria are checked above.
