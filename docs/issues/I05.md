### Response

**Model of the deformation** (`src/C_gamma.py`)
- Relation from `docs/math/C_inhomogeneous_definition.md`: [b_j^s, a_1^σ] = -gb_{σ,j,s} κ. Boson-fermion reordering is the only place it enters: x y = y x + (-gb κ) for boson x left of fermion y. All other relations are unchanged from I03.
- κ is odd and κ² = 0. κ is moved to the front of each monomial with sign (-1)^{F(prefix)}, because κ anticommutes with fermions and commutes with bosons.
- [X,Y]_γ = [X,Y]_0 + κ γ(X,Y), with γ read off as the κ-coefficient of the super-bracket and solved in the Schema 1 basis (sympy `linsolve`, linear in gb).

**Decisions**
- Gb matrix: rows σ ∈ {a_1_p, a_1_m}, columns (j,s) = (b_1_p, b_1_m, b_2_p, …). Shape 2×2n, parity 1. This is the index order recorded in I01.
- **Central K as a target (choice made).** Some κ-parts contain a scalar constant, e.g. the κ-part of [E_eps1_del1_pp, H_1] has constant gb_p_1_p. The Schema 1 basis cannot represent it, because the constants of H_k are fixed. So the first run raised "not in span". Options considered: (a) allow K (the scalar 1, central, parity 0) as an extra target column (chosen); (b) force the constant to match the basis and report non-closure; (c) rescale the basis. Reason for (a): the spec says K is the scalar 1 and is recorded in `central_elements`, so K is the correct target. (b) would mean the deformation does not close, which I did not find. (c) changes Schema 1. With (a), every κ-part is representable.
- Only X ≤ Y (PBW order) entries are stored. The graded symmetry is checked for X < Y.
- gb symbols are named `gb_{σ}_{j}_{s}` (σ, s ∈ {p, m}).

**Bug found and fixed during the run**: `gamma_of` looked up κ-coefficients with keys `(1, m)` when the dict is keyed by monomial. The lookup returned 0 and every γ was empty. Fixed, and the output was checked by hand on the n=1 pair above.
