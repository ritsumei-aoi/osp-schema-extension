### Response

**Files**: `src/C_gamma.py` (γ computation and Schema 2 writer), output `data/C_1_gamma.json` (58 entries), `data/C_2_gamma.json` (330), `data/C_3_gamma.json` (926).

**Method**

- The gb-matrix is $2\times2n$: rows $\sigma\in\{+,-\}$ (`a_1_p`, `a_1_m`), columns $(k,s)$ (`b_k_p`, `b_k_m`). It has $4n$ parameters (`gb_a1p_b1m`, ...). The relation is $[b_k^s,a_1^\sigma]=-\mathrm{gb}_{\sigma,k,s}\,\kappa$, as implemented in the engine (`C_algebra.py`).
- $\gamma(X,Y)$ is the κ-linear part of $[X,Y]_\gamma$, with $X,Y$ basis elements. It is computed exactly and expressed in the basis. Because each κ-term carries one gb, $\gamma(X,Y)=\sum_g \mathrm{gb}_g\,\gamma_g(X,Y)$ and the coefficients are stored as linear forms in gb.
- $\gamma$ is super-skew in $(X,Y)$, so only $i\le j$ is stored.

**Decision 1: K-component.** The κ-linear part of some brackets contains the scalar $1$, which is $K$. For example, $[E_{\varepsilon+\delta_1},H_1]_\gamma$ has κ-part $2\,\mathrm{gb}\,b_1^+b_1^-\,\kappa$, and since $b_1^+b_1^- = -H_2-\tfrac12$, it contains $\kappa\cdot K$. A first run treated this constant as an unexplained residual (10 / 42 / 90 pairs). After adding $K$ as an extra coordinate (`Z: "K"`), all residuals vanish. Schema 2 keeps these as `Z: "K"` entries, separate from the $\mathfrak g$-components. Options considered: (a) drop the K-part (this would silently change the bracket, so rejected), (b) redefine the Cartan generator $H_{n+1}$ to absorb the constant (this would change the basis fixed in I01, so rejected), (c) keep it as an explicit $K$ coordinate. Chose (c).

**Consequence for the docs**: `C_inhomogeneous_definition.md` states $\gamma:\mathfrak g\otimes\mathfrak g\to\mathfrak g$. The K-entries violate this, so they are a real discrepancy. The coboundary definition uses $f:\mathfrak g\to\mathfrak g$, so $\delta f$ never has a K-component. Under the strict reading, every γ with a nonzero K-entry is nontrivial. This is carried into I07 and I08.

- *Consistency with Schema 1*: the κ-free part of every bracket, computed with the deformation switched on, equals the Schema 1 JSON for every $i\le j$ pair, for $n=1,2,3$.
- *Cocycle condition*: the full deformed super-Jacobi identity (κ-free and κ-linear parts together) holds for every ordered triple, so γ is a 2-cocycle with K-components included.
- *Parity*: a separate check over all Schema 2 entries (with $p(K)=0$) gives $p(Z)\equiv p(X)+p(Y)+1$ with 0 violations for $n=1,2,3$ (58, 330, 926 entries). So the K-entries occur only for pairs with $p(X)+p(Y)$ odd, i.e. one even and one odd element.
