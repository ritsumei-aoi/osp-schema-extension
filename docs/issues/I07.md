### Response

**Files**: `src/C_coboundary.py` (δf computation and Schema 4 writer), outputs `data/C_1_coboundary.json` (32 elementary maps, 202 entries), `data/C_2_coboundary.json` (176 maps, 2460 entries), `data/C_3_coboundary.json` (528 maps, 11218 entries). The bracket is taken from Schema 1 JSON via the verifier loader, so it is independent of the oscillator engine.

**Definition of f (decision)**

- An odd linear map must reverse parity. The space of such maps is spanned by the elementary maps $f_{j\to i}: Z_j\mapsto Z_i$ with $p(Z_i)=p(Z_j)+1$ and $Z_m\mapsto0$ for $m\ne j$. Their count is $2\dim\mathfrak g_{\bar0}\dim\mathfrak g_{\bar1}$: $32$, $176$, $528$ for $n=1,2,3$.
- Each elementary map gives one coboundary $\delta f_{j\to i}$. The general $\delta f$ is the linear combination $\sum \phi_{ij}\,\delta f_{j\to i}$, since $\delta$ is linear in $f$. This is the Layer 4 "reference structure".
- Options considered: (a) store $\delta f$ for the general parameterized $f$ with symbolic $\phi_{ij}$; (b) store one $\delta f$ per elementary map. Chose (b), since it is exact, avoids symbolic solving here, and lets I08 build the linear system directly.
- $f:\mathfrak g\to\mathfrak g$, as in `C_coboundary_definition.md`. No K-component is allowed in $f$. This matters for I08 (see I05).

**Formula**: $(\delta f)(X,Y)=(-1)^{p(X)}[X,f(Y)]-(-1)^{(p(X)+1)p(Y)}[Y,f(X)]-f([X,Y])$, exactly as in the doc. The stored entries are for $a\le b$, with $Z\in\mathfrak g$.

**Checks (run output of `python3 src/C_coboundary.py`)**

```
n=1: 32 elementary maps, 202 entries, parity violations 0, cocycle checked on 32 maps, failing 0
n=2: 176 elementary maps, 2460 entries, parity violations 0, cocycle checked on 30 maps, failing 0
n=3: 528 elementary maps, 11218 entries, parity violations 0, cocycle checked on 30 maps, failing 0
```

- *Parity / basis consistency*: every entry of every $\delta f$ has $Z$ in the Layer 1 basis and $p(Z)=p(X)+p(Y)+1$. Zero violations for all maps.
- *Cocycle condition*: $\delta f$ must satisfy the linearized Jacobi identity for the odd parameter $\kappa$, which is $(-1)^{p(X)}[X,\gamma(Y,Z)]+\gamma(X,[Y,Z])-[\gamma(X,Y),Z]-\gamma([X,Y],Z)-(-1)^{p(X)p(Y)+p(Y)}[Y,\gamma(X,Z)]-(-1)^{p(X)p(Y)}\gamma(Y,[X,Z])=0$. The signs were derived from $[X,\kappa W]=(-1)^{p(X)}\kappa[X,W]$. For $n=1$ all 32 maps were checked, and for $n=2,3$ a seeded sample of 30 maps each. All passed.
- *Sensitivity*: the same check applied to a wrongly signed $\delta f$ (sign flipped on the odd-odd and even-even terms) gives 585 failing triples on 12 maps, against 0 with the correct convention. So the check can fail and the sign convention in the doc is consistent.
- *Caveat*: n=2,3 cocycle checks are on sampled maps, not all maps. Since $\delta$ is linear in $f$, a failure would show on the elementary basis; the sample is a partial check, and the full check is not run.

**Note**: The K-component of $\gamma$ (I05) is not in the image of $\delta$ on $f:\mathfrak g\to\mathfrak g$, because every $\delta f$ has $Z\in\mathfrak g$. This is analysed in I08.
