### Response

**Odd map $f$ (decision)**: $f(Z_j)=\sum_i \phi_{ij} Z_i$, nonzero only when $p(Z_i)\neq p(Z_j)$. Options considered: (a) a fixed numerical $f$; (b) the full parameter family $\phi_{ij}$ (chosen). Reason: triviality means $\gamma=\delta f$ for some $f$, so the Schema 4 data must be linear in $\phi$ to allow solving for $\phi$ in I08. The number of parameters is $2\cdot(\dim\mathfrak g_{\bar0})(\dim\mathfrak g_{\bar1})$: $32$, $176$, $528$ for $n=1,2,3$.

**Coboundary**: $(\delta f)(X,Y)=(-1)^{p(X)}[X,f(Y)]-(-1)^{(p(X)+1)p(Y)}[Y,f(X)]-f([X,Y])$, with the $\kappa$-free Schema 1 bracket. It is independent of gb. For each unit map $f_{ij}:Z_j\mapsto Z_i$, the tensor is computed directly from the three terms, so the output stores the coefficient of each $\phi_{ij}$ in each $(\delta f)(X,Y)^Z$.

**Implementation**: `src/C_coboundary.py` writes `data/C_{1,2,3}_coboundary.json` (216, 2768, 13848 nonzero terms).

**Checks** (stored in each JSON `consistency` block):
- parity: $p((\delta f)(X,Y)) = p(X)+p(Y)+1$ for all terms. True for $n=1,2,3$.
- cocycle: each $\delta f$ satisfies the $\kappa$-linear super Jacobi condition. For $n=1,2$ every unit map is checked. For $n=3$, checking all 528 units one by one is too slow in pure Python (the first attempt at this was stopped). Instead one seeded random integer combination of all units is checked. The Jacobi expression is linear in the cochain, so a single failing unit would almost certainly show up as a nonzero residual. This is a probabilistic argument, not an exhaustive check, and it is stated as such.

**Bug found and fixed (harness)**: the first version ran the per-unit cocycle check for all $n$, and at $n=3$ it did not finish within the 120 s timeout. Cause: $O(N^3)$ triple loops times 528 units, in pure Python. Fixed as described above. The background run was stopped and the output rewritten.
