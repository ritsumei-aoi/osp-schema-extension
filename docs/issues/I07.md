### Response

**Implementation** (`src/C_coboundary.py`)
- `delta_f(n, f)` implements `(δf)(X,Y) = (−1)^{p(X)}[X,f(Y)] − (−1)^{(p(X)+1)p(Y)}[Y,f(X)] − f([X,Y])` literally from the Schema 1 JSON structure constants (K central ⇒ [X,K]=0).
- f is parameterized by φ_{ZX} with p(Z)=p(X)+1 (`phi_slots`).
- Sign-convention check: for odd Z0, f = ad(Z0) is an odd derivation and must give δf = 0; verified for every odd generator, n=1,2,3.

**Decision: which f?** Options: (a) arbitrary/random f (no relation to Layer 3, useless for comparison); (b) f solving δf = γ by numerical least squares (non-unique, floating point); (c) a closed-form f from the physical origin of the deformation. **Chosen (c)**: the redefinition a_1^σ → a_1^σ + κ c^σ with c^σ = Σ_j (gb_{σ,j,−} b_j^+ − gb_{σ,j,+} b_j^−) removes the exchange relation `[b_j^s,a^σ] = −gb κ` (since [b_j^−,b_j^+]=1, [b_j^+,b_j^−]=−1), preserves CAR (κ²=0) and induces X ↦ X + κ f_red(X). Then γ = −δ f_red, so **f_gb := −f_red** satisfies δf_gb = γ(gb). For the all-plus profile, n=1: f(E_eps1_del1_pp) = E_2del1_p·(…), f(H_1) ∝ E_eps1_del1_mp etc. (see `C_1_coboundary.json`). A bug found and fixed along the way: κ's sign was applied twice (explicitly and by the engine), which made σ=m parameters fail; after the fix δ(−f_red) = γ exactly for all single parameters and for random integer gb, n=1,2,3.

**Ambiguity / decision (K-valued f)**: f_gb takes values in g ⊕ ℂK (e.g. f(E_eps1_del1_pm) contains −½K for n=1). The issue says f: g → g. A strict f: g→g cannot produce the K-components of γ (δf has no K-component when f has none, since [·,K]=0 and [g,g]⊂g). Recorded both: main files (codomain g+ℂK; shifts of even generators by multiples of κ are legitimate in A = V⊕ℂK⊕ℂκ) and `C_{n}_coboundary_strictg.json` (K-parts dropped). I08 analyses both.
