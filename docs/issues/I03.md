### Response

#### Implementation
* `src/oscillator.py` — exact engine for the oscillator algebra: letters `kappa, a_1_p, a_1_m, b_k_p, b_k_m`,
  normal ordering by repeated adjacent swaps using the elementary brackets
  ({a_1_m,a_1_p}=1, [b_k_m,b_k_p]=1, (a_1_±)^2=0, κ²=0, κ supercentral, optional
  [b_k_s,a_1_σ] = −gb·κ). Coefficients are `LinPoly` (polynomials in gb symbols over `Fraction`), so
  everything is exact and the same engine serves I05–I07. Also contains a rational `Decomposer`
  (Gaussian elimination) that writes an algebra element as Σ c_Z Z + c_1·1 and **raises** if the element
  is outside span(basis ∪ {1}).
* `src/C_generators.py` — basis labels/ordering from `handover/notation.md`, oscillator realizations,
  `compute_brackets(n)` (all ordered pairs; raises if any bracket has a constant term), and the Schema 1
  writer `build_structure_json(n)` / `write_structure(n)`.
* `tests/test_C_structure.py` — 31 tests.

Options considered for the computation: (a) sympy noncommutative symbols — rejected (slow, awkward
normal ordering of fermions/κ); (b) matrix representation of osp(2|2n) — rejected because the
deformation in I05 lives in the oscillator algebra, not in a finite matrix rep; (c) own normal-ordering
engine with exact rationals — chosen.

#### Decisions / checks
* Brackets are computed as $[X,Y\}=XY-(-1)^{p(X)p(Y)}YX$ in the oscillator algebra and decomposed; the
  generator asserts that **no constant term** ever appears (confirmed for n=1,2,3 — this validates the
  choice of the Frappat Cartan elements including the −1/2 in $H_{n+1}$).
* All ordered pairs are stored (so antisymmetry is checkable from the data in I04).
