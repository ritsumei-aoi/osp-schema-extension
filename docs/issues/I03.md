### Response

**Implementation (2026-10-08, no-gate)**

Files:
- `src/oscillator_algebra.py` — exact engine for the Weyl–Clifford algebra generated by
  `kappa < a_1_p < a_1_m < b_1_p < b_1_m < ... < b_n_p < b_n_m`. Elements are dicts
  `normal-ordered word -> sympy coefficient`; normal ordering is done by recursive adjacent swaps
  `x y = (-1)^{p(x)p(y)} y x + [x,y}` with memoization; nilpotent odd squares `(a_1^±)^2 = kappa^2 = 0`.
  The same engine supports the gb-deformed relation `[b_j^s, a_1^σ] = -gb kappa` (used in I05).
- `src/C_generators.py` — basis (`even_basis`, `odd_basis`, `basis`), `parity_table`, `root_vector`,
  `realization` (standard forms + Frappat strings), `Decomposer` (expresses any quadratic element in the
  basis of g ⊕ CK: root vectors are single words; the (n+2)-dim Cartan+K system is inverted once, exactly),
  `structure_constants` (all ordered pairs), `build_schema1`, `write_schema1`. CLI writes `data/C_{n}_structure.json`.
- `data/C_1_structure.json`, `data/C_2_structure.json`, `data/C_3_structure.json`.
- `tests/test_C_structure.py` (+ `tests/conftest.py`).

Design choices:
1. Structure constants are computed **from the oscillator realization** (graded commutator in the
   enveloping algebra), not from a Chevalley-basis table, so they are tied to the realization that the
   deformation (I05) will modify. The `Decomposer` asserts that no `K` component appears in the
   undeformed brackets (true for all three n, confirming that the constants in `H_{n+1}` are correct).
2. All ordered pairs (X, Y) are stored (40 / 198 / 528 non-zero entries for n = 1 / 2 / 3), as specified in I02.
3. Rationals are strings; coefficients are integers here except that the decomposition machinery
   supports halves (needed for `-1/2` in `H_{n+1}`).

Sample output (n = 1, from `data/C_1_structure.json`):
