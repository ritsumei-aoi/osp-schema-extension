### Response

**Method**
- Elements are linear combinations of normal-ordered oscillator monomials (`src/C_generators.py`). Normal order is a_1_m < a_1_p < b_1_m < b_1_p < b_2_m < ..., with a_1_p a_1_m = 1 - a_1_m a_1_p, a_1_p² = a_1_m² = 0, and [b_k_m, b_k_p] = 1.
- Super-bracket [X,Y] = XY - (-1)^{pX pY} YX. Each bracket is solved over Q (sympy `linsolve`) in the basis. The solver raises if a bracket leaves the span.
- Structure constants are stored for pairs with index X ≤ Y in PBW order, one entry per nonzero Z.

**Decisions**
- Cartan: H_1 = a_1^+a_1^- + b_1^+b_1^-, H_k = b_{k-1}^+b_{k-1}^- - b_k^+b_k^- (2≤k≤n), H_{n+1} = -b_n^+b_n^- - 1/2. These follow `docs/math/Cn1_definition.md`.
- Even root generators use the uniform form E_{±2δ_k} = (b_k^±)². `Cn1_definition.md` gives a ½ factor for the simple root E_{2δ_n} but the uniform form for all roots. I chose the uniform form for all k. The ½ only rescales one generator, so closure and the bracket structure are unaffected.
- Odd generators are a_1^+ b_k^± (ε roots) and a_1^- b_k^± (−ε roots), matching the label table in `handover/notation.md` §5.
- The even ordering within the block is Cartan, then E_2del{k}_p/m by k, then E_del{i}_del{j}_* by (i,j, pattern). Odd is by (k, pattern pp<pm<mp<mm). This is a concrete refinement of the lexicographic rule in notation.md §6.
- Schema fields: as in `json_schema_specification.md` §3. `generator_realization` stores the defining words as written (not normal-ordered). `generation_date` is hard-coded to 2026-10-08.

**Execution log**
- `python3 src/C_generators.py` wrote `data/C_1_structure.json` (20 brackets), `data/C_2_structure.json`, and `data/C_3_structure.json`.
- Counts from the generated files: n=1: 8 (4 even, 4 odd); n=2: 19 (11, 8); n=3: 34 (22, 12). These match the dimension table.
- Spot check (n=1): [E_2del1_p, E_2del1_m] = 4 H_2. This agrees with the identity [(b⁻)², (b⁺)²] = 4b⁺b⁻ + 2, since H_2 = -b⁺b⁻ - 1/2.
- Closure: all brackets for n=1,2,3 lie in the span (no ValueError). Brackets are 20, 99, and 264.
