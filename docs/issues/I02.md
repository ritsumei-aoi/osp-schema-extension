## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Decisions**
- Wrote `docs/json_schema_specification.md` (Schema 1 complete; Schemas 2-4 sections are added in I05-I07 as the issues request).
- Followed the mandatory unified rules: `algebra.m=1` with dimension formulas `2n^2+n+1` / `4n`; `oscillator_generators` has exactly `fermions` (m=1, `a_1_p`,`a_1_m`) and `bosons` (rank n); `central_elements` is top-level with `kappa` (parity 1) and `K` (parity 0); files `C_{n}_structure.json` with n = bosonic rank.
- Options considered for `structure_constants`: (a) store only X<Y pairs, (b) store all ordered pairs. Chose (b) so antisymmetry is an actual check on the data, at the cost of ~2x size.
- Options considered for `schema_version`: bump to "5.1" vs keep "5.0". Kept "5.0" since all changes are additive/family-specific and the task statement calls this "v5.0 extension".
- Ambiguity: the doc says K is "identified with the scalar 1 and excluded from basis". I keep it only in `central_elements`; consequences for the deformation (a κ·K residue) are handled in I05 and I08.
- Compatibility table (section 1.9) documents key-by-key differences vs B(0,n)/B(m,n).

**Verification**: the spec is a document; its field lists are enforced by tests written in I03 (`tests/test_C_generators.py::test_schema1_*`).
