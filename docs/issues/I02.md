## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

#### Analysis & Decisions

**1. Schema 1 Fields for C(n+1)**

Created comprehensive JSON schema specification with all required fields:

**New/Modified fields**:
- **`algebra` field**: Fixed m=1 for C(n+1), dimension formulas (even=2n²+n+1, odd=4n)
- **`central_elements` field** (NEW): Top-level key containing κ (odd) and K (even)
- **`oscillator_generators` field** (MODIFIED): Removed `supplementary_fermion`, added `fermions` with CAR pair labels (a_1_p, a_1_m)
- **`oscillator_relations` field** (MODIFIED): Replaced a_0 relations with CAR anticommutator {a_1^-, a_1^+} = 1

**Unchanged fields**:
- `basis`, `parity`, `generator_realization`, `structure_constants`, `metadata`
- All maintain consistency with v5.0 structure

**2. Central Elements Structure**

Defined two central elements:
- **κ (kappa)**: Parity 1, nilpotent (κ² = 0), appears in PBW ordering
- **K**: Parity 0, identity element (excluded from basis, included in schema for completeness)

This aligns with the mathematical definition in `C_coboundary_definition.md`.

**3. File Naming Convention**

Finalized naming scheme:
```
C_{n}_structure.json     → n = bosonic rank (1, 2, 3)
C_{n}_gamma.json         → C(n+1) deformation parameters
C_{n}_evaluated.json     → Evaluated structure with gb substitution
C_{n}_coboundary.json    → Coboundary reference structure
```

Mapping:
- C(2) = osp(2|2) → n=1 → C_1_structure.json
- C(3) = osp(2|4) → n=2 → C_2_structure.json
- C(4) = osp(2|6) → n=3 → C_3_structure.json

**4. Backward Compatibility**

Documented compatibility matrix:
- B(m,n) and C(n+1) share the same v5.0 schema architecture
- Key differences:
  - Oscillator generators (supplementary vs. CAR pair)
  - Odd root structure (δ-roots vs. ε-roots)
  - Central elements (not present in B, present in C)
- All structural differences localized to specific JSON keys
- PBW ordering convention consistent across families
