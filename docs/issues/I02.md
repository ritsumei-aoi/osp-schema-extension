## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

#### Deliverable

Created `docs/json_schema_specification.md` (the file did not exist in the repository, so

#### Decisions per requirement

1. **`algebra`**: `family="C"`, `m=1`, `n`, `cartan_type="C(n+1)"`, `alternative_notation.osp="osp(2|2n)"`,
   `dimension_formula="osp(2m|2n) with m=1"`, plus an explicit `dimension_formulas` object
   (`even: 2n^2+n+1`, `odd: 4n`, `total: 2n^2+5n+1`) and numeric `dimension` (mandatory rule satisfied).
2. **`oscillator_generators`**: `fermions` {m:1, count:2, labels [a_1_p, a_1_m], parity 1} and
   `bosons` {n, count 2n, labels, parity 0}. `supplementary_fermion` removed (mandatory rule satisfied).
3. **`oscillator_relations`**: `standard_fermion_anticommutators` ({a_1^-, a_1^+}=1, (a_1^±)^2=0),
   `bosonic_commutators` (unchanged), `mixed_commutators` ([b, a_1]=0 undeformed), plus `normal_order`.
4. **`central_elements`** (top-level): `kappa` parity 1, `kappa^2=0`, odd central; `K` parity 0,
   identified with 1. Neither is in the basis.
   *Ambiguity recorded*: `B0n_definition.md` §3 says κ is listed "with parity 0" in the B(0,n) JSON, while
   the I02 mandatory rule (and the mathematics, κ odd) say parity 1. I follow the mandatory rule: parity 1.
5. **File naming**: `C_{n}_structure.json` etc. with n = bosonic rank (C(2)→`C_1_…`). Confirmed and recorded
   in both the spec and `handover/notation.md` §1. For Layer 3/4 the issues I06/I07 prescribe
   `C_{n}_evaluated.json` / `C_{n}_coboundary.json` (no `<gb>` suffix); I adopt those names for the
   representative evaluation and reserve `C_{n}_evaluated_<profile>.json` for additional sign profiles.

#### Other design choices

* `structure_constants` stores **all ordered pairs** (X,Y) with a nonzero bracket (not only X<Y) so that
  I04 can verify graded antisymmetry from the file itself.
* `basis` gains informational keys `cartan` and `pbw_order`; the `even`/`odd` lists are in PBW order.
* `schema_version` stays "5.0": the C(n+1) file is a superset-by-addition / family-switch of v5.0; a
  version bump was considered and rejected because no existing v5.0 key changes type.
* Alternative considered for `central_elements`: nesting under `oscillator_relations` (as the B(0,n) spec
  text suggests). Rejected because the I02 mandatory rule requires a top-level key.

#### Compatibility with B(m,n)

Documented in the spec as a key-by-key table: unchanged keys keep name and type, the fermion-sector
keys are replaced, new keys are additive, and a generic reader branches on `algebra.family`.

#### Verification

The spec is validated by construction in I03: `src/C_generators.py` emits exactly the keys listed here
and `tests/test_C_structure.py` asserts their presence, the mandatory `m=1` / dimension-formula strings,
and the top-level `central_elements` with `kappa.parity == 1`, `K.parity == 0`.
