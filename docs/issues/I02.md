## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Decisions

1. **`algebra`**: `family="C"`, `m=1`, `n`=bosonic rank, `cartan_type="C(n+1)"`,
   `alternative_notation.osp="osp(2|2n)"`, `dimension` block with explicit
   `formulas: {even: "2n^2 + n + 1", odd: "4n", total: "2n^2 + 5n + 1"}`, plus
   `even_subalgebra="so(2) + sp(2n)"` and `rank=n+1` (spec §1.2).
2. **`oscillator_generators`**: exactly two keys, `fermions` (`m=1`, labels `a_1_p, a_1_m`,
   parity 1) and `bosons` (`n`, labels `b_k_p, b_k_m`, parity 0). `supplementary_fermion` removed.
3. **`oscillator_relations`**: `standard_fermion_anticommutators` (`{a_1^-, a_1^+} = 1`,
   `(a_1^±)^2 = 0`), `bosonic_commutators` unchanged, `mixed_commutators` = 0 (undeformed),
   plus `normal_ordering` string.
4. **`central_elements`** (top-level): `kappa` (parity 1, κ²=0, odd central, not in basis) and
   `K` (parity 0, identified with 1, not in basis). Option considered and rejected: putting
   `central_elements` inside `oscillator_relations` as the B0n_schema_v5 note suggests —
   rejected because the I02 mandatory rule requires a top-level key.
5. **File naming**: `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated.json`
   (plus `C_{n}_evaluated_<profile>.json` for extra sign profiles), `C_{n}_coboundary.json`,
   with `n` the bosonic rank (C(2) → `C_1_*`).
6. **Additive keys**: `schema_layer` (1–4), `basis.pbw_order`,
   `structure_constants_convention`; all ordered pairs are stored in `structure_constants` so
   that antisymmetry is a checkable property of the file (I04).
7. **Forward design of Schemas 2–4** (needed so that I03–I07 outputs conform to one document):
   gb parameters `gb_a1{σ}_b{j}{s}` in a 2×2n `gb_matrix`; symbolic γ entries as linear forms
   `{"param": "rational"}`; evaluated γ as rationals; Schema 4 with `f_parameterization`,
   `coboundary_symbolic`, `representative_f`, `coboundary_evaluated`. The target of γ is
   declared as `g + C K` because the deformed bracket of two symmetrized quadratics can
   produce a constant (K) term; this is justified and verified in I05.
