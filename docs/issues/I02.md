## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Deliverable
`docs/json_schema_specification.md` created. It specifies Schema 1 completely for C(n+1) and, so that
I05–I07 have a fixed target, also Schemas 2–4.

#### Decisions (per requirement)
1. **`algebra`**: `family="C"`, `m=1`, `n`, `cartan_type="C(n+1)"`, `alternative_notation.osp="osp(2|2n)"`,
   `dimension_formula = {even: "2n^2 + n + 1", odd: "4n", total: "2n^2 + 5n + 1"}`, numeric `dimension`,
   plus two additive fields `even_subalgebra="so(2) + sp(2n)"` and `rank=n+1`.
   Option considered and rejected: putting the formulas inside `alternative_notation` as B(0,n) does
   ("osp(2m+1|2n) with m=0"); the mandatory rule asks for explicit even/odd formulas, so a dedicated
   `dimension_formula` object is used and `alternative_notation.dimension_formula` keeps the B(0,n)-style string.
2. **`oscillator_generators`**: exactly two keys, `fermions` (`m=1`, labels `a_1_p, a_1_m`, parity 1) and
   `bosons` (`n`, `count=2n`, labels, parity 0). No `supplementary_fermion`.
3. **`oscillator_relations`**: `standard_fermion_anticommutators` (`{a_1^-, a_1^+} = 1`, `(a_1^±)^2 = 0`),
   `bosonic_commutators` (unchanged), `mixed_commutators` (`[b_i^±, a_1^±] = 0`, with a pointer to the Schema 2 deformation).
4. **`central_elements`** is a **top-level** key with `kappa` (parity 1, nilpotent, supercentral, not in basis,
   PBW-first) and `K` (parity 0, identified with 1, not in basis). Ambiguity resolved: B(0,n) v5.0 says
   kappa is listed "with parity 0"; the mandatory rule for this issue and the mathematics say parity 1.
   I follow the mandatory rule (parity 1) and record the discrepancy in the spec.
5. **File naming**: `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated[_{profile}].json`,
   `C_{n}_coboundary[_{profile}].json`, with `n` the bosonic rank (C(2) ↔ `n=1`). Confirmed against
   `B0n_schema_v5.md` ("C(2)=osp(2|2) is `C_1_structure.json`").

#### Compatibility with B(m,n)
Documented in the spec's last section: all B(0,n) keys and value shapes retained; the only
structural changes are `fermions` vs `supplementary_fermion`, `standard_fermion_anticommutators` vs
`supplementary_fermion_relation`, and the additive `central_elements`, `basis.pbw_order`,
`root`/`root_vector` fields. A B(0,n) reader branching on `algebra.family` can consume both.

#### Verification
Spec reviewed against the three mandatory unified rules (algebra field, oscillator generators,
central elements, file naming) — all four satisfied. Mechanical conformance of the generated JSON to this
spec is tested in I03 (`tests/test_C_structure.py`).
