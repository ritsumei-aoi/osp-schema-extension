## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

#### Analysis & Decisions

**1. Algebra Field Design**

```json
{
  "family": "C",
  "m": 1,
  "n": 2,
  "cartan_type": "C(3)",
  "alternative_notation": {
    "osp": "osp(2|4)",
    "dimension_formula": "osp(2m|2n) with m=1"
  },
  "dimension": {
    "total": 19,
    "even": 11,
    "odd": 8
  }
}
```

**Decision**: Include explicit `m=1` for all C(n+1) algebras, following Frappat's osp(2m|2n) parametrization. Dimension formulas are mandated: even = 2n²+n+1, odd = 4n.

**2. Oscillator Generators Design**

**B(0,n) convention**:
```json
{
  "supplementary_fermion": {...},
  "bosons": {...}
}
```

**C(n+1) convention**:
```json
{
  "fermions": {
    "label": "a_1",
    "m": 1,
    "parity": 1,
    "relation": "{a_1^-, a_1^+} = 1",
    "labels": ["a_1_p", "a_1_m"]
  },
  "bosons": {...}
}
```

**Decision**: Replace `supplementary_fermion` with `fermions` key containing standard CAR pair (a_1^+, a_1^-). Include parameter m=1 to document fermionic dimension.

**3. Oscillator Relations for Standard Fermionic Pair**

```json
{
  "standard_fermion_anticommutators": {
    "description": "Canonical anticommutation relations for standard fermionic pair",
    "relations": {
      "pair": "{a_1^-, a_1^+} = 1",
      "same": "{a_1^±, a_1^±} = 0"
    }
  },
  "bosonic_commutators": {...},
  "mixed_anticommutators": {
    "fermion_boson": "{a_1^±, b_j^±} = 0"
  }
}
```

**Decision**: Replace `supplementary_fermion_relation` with `standard_fermion_anticommutators` containing CAR. Add `mixed_anticommutators` key to explicitly document fermion-boson vanishing anticommutation.

**4. Central Elements (`central_elements` top-level key)**

```json
{
  "kappa": {
    "label": "κ",
    "parity": 1,
    "nilpotency": "κ^2 = 0",
    "description": "Odd central element used in inhomogeneous deformation"
  },
  "K": {
    "label": "K",
    "parity": 0,
    "note": "Even central element (formal identity); identified with scalar 1 in applications"
  }
}
```

**Decision**: Make `central_elements` a mandatory top-level key (not nested). This is essential because:
- κ appears in the deformed bracket [X,Y]_γ = [X,Y]₀ + κ·γ(X,Y)
- Both κ and K must be visible throughout all schema layers (structure constants, deformation parameters, coboundary calculations)
- It clarifies the algebraic architecture upfront

**5. File Naming Convention**

| Algebra | File Pattern | Examples |
|---------|--------------|----------|
| C(n+1) = osp(2\|2n) | `C_n_structure.json` | C(2)→`C_1_structure.json`, C(3)→`C_2_structure.json`, C(4)→`C_3_structure.json` |

**Decision**: Use `C_n_structure.json` where n is the bosonic rank (not n+1). This is consistent with parametrization: C(n+1) has n bosonic oscillators b_1,...,b_n. Files expand to:
- `C_n_structure.json` (Layer 1: algebra structure)
- `C_n_gamma.json` (Layer 2: deformation)
- `C_n_evaluated_<gb>.json` (Layer 3: numerical evaluation)
- `C_n_coboundary_<gb>.json` (Layer 4: coboundary analysis)

#### Backward Compatibility Analysis

All changes are **additive** and maintain full compatibility with B(0,n) schema:
- New `family` values ("C") don't conflict with existing ("B")
- New `central_elements` key doesn't break existing parsers
- B(0,n) files continue to use `supplementary_fermion` key
- Schema version remains "5.0" for all algebras
