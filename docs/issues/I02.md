## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### 1. Schema 1 Field Definitions & Mandatory Unified Rules
- **`algebra` Field**: Set `family="C"`, `m=1`, `n=rank`, dimension formulas `even: 2n^2 + n + 1`, `odd: 4n`, `total: 2n^2 + 5n + 1`.
- **`oscillator_generators`**: Structurally separated into `fermions` (`m=1`, labels `["a_1_p", "a_1_m"]`) and `bosons` (`n=rank`, labels `["b_1_p", "b_1_m", ...]`). Supplementary fermion $a_0$ eliminated.
- **`oscillator_relations`**: CAR specified via `standard_fermion_anticommutators` (`{a_1^-, a_1^+} = 1`) alongside CCR `bosonic_commutators`.
- **`central_elements`**: Created top-level key holding `kappa` (parity 1, nilpotent) and `K` (parity 0, scalar identity).
- **File Naming**: Fixed to `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated_<gb>.json`, `C_{n}_coboundary_<gb>.json` where $n$ is the bosonic rank (e.g. $n=1$ for $C(2)$).

#### 2. Options Considered & Justifications
- *Option 1*: Keep `oscillator_generators` unified with `supplementary_fermion` key set to null.
- *Option 2 (Selected)*: Explicitly replace `supplementary_fermion` with a dedicated `fermions` key for CAR fermions and add top-level `central_elements`.
- *Reasoning*: Option 2 accurately models the algebraic distinction between $B(0,n)$ (non-CAR $a_0$) and $C(n+1)$ (standard CAR pair $a_1^\pm$) while standardizing schema validation rules.
