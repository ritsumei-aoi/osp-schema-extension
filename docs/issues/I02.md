## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### 1. Schema 1 Field Definitions for C(n+1)

In compliance with the mandatory unified rules and requirements:
1. **`algebra` Field**:
   - `family`: `"C"`
   - `m`: `1` (indicating standard fermionic pair $a_1^+, a_1^-$)
   - `n`: bosonic rank ($n=1, 2, 3$)
   - `cartan_type`: `"C(n+1)"` (e.g., `"C(2)"` for $n=1$)
   - `alternative_notation`: contains `"osp"`: `"osp(2|2n)"` and explicit dimension formulas:
     - `even`: `"2*n^2 + n + 1"`
     - `odd`: `"4*n"`
     - `total`: `"2*n^2 + 5*n + 1"`
   - `dimension`: `{ "total": 2*n^2 + 5*n + 1, "even": 2*n^2 + n + 1, "odd": 4*n }`

2. **`central_elements` Field (Top-Level Key)**:
   - `kappa`: odd central element with `parity: 1`, `nilpotent_order: 2`, `relation: "kappa^2 = 0"`.
   - `K`: even central element with `parity: 0`, `relation: "K = 1"`.

3. **`oscillator_generators` Field**:
   - `fermions`: `{ "count": 2, "m": 1, "labels": ["a_1_p", "a_1_m"], "description": "Standard fermionic CAR pair a_1^±" }`
   - `bosons`: `{ "count": 2*n, "n": n, "labels": ["b_1_p", "b_1_m", ...], "description": "Bosonic oscillators b_i^± with i=1,...,n" }`

4. **`oscillator_relations` Field**:
   - `standard_fermion_anticommutators`: `{a_1^±, a_1^±} = 0$, $\{a_1^-, a_1^+\} = 1$.
   - `bosonic_commutators`: $[b_i^-, b_j^+] = \delta_{ij}$, $[b_i^\pm, b_j^\pm] = 0$.
   - `mixed_commutators`: $[b_i^\pm, a_1^\sigma] = 0$.

5. **`basis` and `parity` Fields**:
   - Uses the PBW Option A ordering established in I01 and `handover/notation.md`.
   - Complete parity mapping ($0$ for even, $1$ for odd).

6. **`generator_realization` and `structure_constants`**:
   - Rational normal-ordered polynomial expressions for all generators.
   - Graded bracket representation $[X, Y\} = XY - (-1)^{p(X)p(Y)} YX$.

#### 2. Compatibility with B(m,n) Schema
- Fully documented in `docs/json_schema_specification.md` section "Comparison and Compatibility with B(0,n)".
- Eliminates the non-standard auxiliary fermion $a_0$ in favor of standard CAR pairs ($m=1$).
- Promotes `central_elements` to an explicit top-level key for transparent algebraic typing.

#### 3. File Naming Conventions
- Confirmed file naming: `data/C_{n}_structure.json`, `data/C_{n}_gamma.json`, `data/C_{n}_evaluated.json`, `data/C_{n}_coboundary.json`, where $n$ is the bosonic rank ($n=1$ for $C(2)$, $n=2$ for $C(3)$, $n=3$ for $C(4)$).
