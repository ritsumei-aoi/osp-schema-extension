## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Result**: `docs/json_schema_specification.md` created: full standalone Schema 1 spec for C(n+1) (all keys), a B(m,n) compatibility table, file naming. Schemas 2-4 sections to be appended in I05-I07 (overview table already lists them).

**Decisions (with options considered)**
- `algebra`: includes `"m": 1`, dimension formulas even 2n²+n+1, odd 4n (mandatory rule); dims verified against generated data.
- `oscillator_generators`: keys `fermions` (labels a_1_p, a_1_m, m=1) and `bosons`. Option considered: keep `supplementary_fermion` key with a pair; rejected (would misrepresent a CAR pair as an auxiliary fermion).
- `oscillator_relations`: `standard_fermion_anticommutators` replaces the supplementary relation.
- `central_elements`: top-level, `kappa` parity 1, `K` parity 0 (mandatory rule). Ambiguity: `B0n_definition.md` says κ is listed with parity 0 in B(0,n)'s JSON, while `C_inhomogeneous_definition.md` says κ is odd. Adopted odd (mandatory rule + C document); documented in the spec. K is identified with scalar 1 and not a basis element (as in B(0,n)).
- `structure_constants`: both orderings (X,Y) and (Y,X) are stored. Option: store only X<Y. Rejected, because the antisymmetry check in I04 would then be vacuous.
- File naming: `C_{n}_structure.json`, n = bosonic rank (C(2) ↔ n=1), confirmed; same stem for later layers.
- Compatibility: superset of B(0,n) keys; readers dispatch on `algebra.family`; the only breaking replacements are the two fermion-related keys.

**Verification**: generated `data/C_{1,2,3}_structure.json` contain exactly the keys listed in the spec (checked in I03 tests).
