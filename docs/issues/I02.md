## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Summary
Created `docs/json_schema_specification.md` (complete standalone C(n+1) v5.0 spec; Schema 1 in full, Schemas 2–4 outlined and refined in I05–I07).

#### Decisions
- **`algebra`**: `family "C"`, `"m": 1`, `cartan_type "C(n+1)"`, `dimension_formulas` {even `2n^2 + n + 1`, odd `4n`, total `2n^2 + 5n + 1`} plus numeric `dimension` (mandatory rule satisfied).
- **`oscillator_generators`**: exactly two keys `fermions` (m=1, `a_1_p, a_1_m`) and `bosons` (rank n) — mandatory rule.
- **`oscillator_relations`**: `standard_fermion_anticommutators` ({a_1^-, a_1^+} = 1, nilpotency), `bosonic_commutators` (unchanged from B), `mixed_commutators` (undeformed, = 0).
- **`central_elements`**: top-level; `kappa` parity 1 (κ² = 0), `K` parity 0 (K = 1) — mandatory rule.
- **File naming**: `C_{n}_structure.json`, n = bosonic rank (C(2) → `C_1_structure.json`). Other layers: `C_{n}_gamma.json`, `C_{n}_evaluated[_{profile}].json`, `C_{n}_coboundary.json`.
- **`structure_constants`**: stored for *all ordered pairs* (B-spec example did not say whether both orders are stored). Options: (a) only X ≤ Y in PBW order, smaller file; (b) all ordered pairs. Chose (b) so that antisymmetry in I04 is a genuine data check rather than true by construction.
- Added `basis.ordering` (full PBW list) as the single index order for all layers.

#### Ambiguity recorded
`B0n_schema_v5.md`/`B0n_definition.md` state that κ is listed "with parity 0" in `central_elements`, while the same document (and the C(n+1) docs) define κ as odd. Options: keep parity 0 for B-compatibility, or use parity 1. The mandatory unified rule for this issue fixes **parity 1**; I followed it and documented the difference in the compatibility table.

#### Compatibility with B(m,n)
Documented in spec §2 (key-by-key table): `schema_version`, `bosons`, `bosonic_commutators`, `parity`, `generator_realization`, `structure_constants`, `metadata` formats are identical; fermion keys renamed; `central_elements` and `basis.ordering`, `algebra.dimension_formulas` are additive.
