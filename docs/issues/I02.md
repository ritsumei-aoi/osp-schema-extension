## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Date**: 2026-10-06 — deliverable: `docs/json_schema_specification.md` (complete standalone spec, Schema 1 in full, Layers 2–4 outlined and filled in I05–I07).

#### Decisions
1. `algebra`: `family="C"`, `m=1`, `n`, `cartan_type="C(n+1)"`, `alternative_notation.osp="osp(2|2n)"`,
   `dimension_formulas` = {even `2n^2 + n + 1`, odd `4n`, total `2n^2 + 5n + 1`} plus numeric `dimension`.
2. `oscillator_generators`: two keys `fermions` (`m=1`, labels `a_1_p, a_1_m`) and `bosons` (rank `n`); no supplementary fermion.
3. `oscillator_relations`: `standard_fermion_anticommutators` ({a_1^-,a_1^+}=1, (a_1^±)^2=0), `bosonic_commutators` (CCR, unchanged), `mixed_commutators` ([b,a]=0 undeformed), and the normal order.
4. `central_elements` top-level: `kappa` (parity 1, κ²=0) and `K` (parity 0, K=1, excluded from basis).
5. File naming: `C_{n}_structure.json` with `n` the bosonic rank (C(2)→`C_1`). For Layers 3/4 I store all gb profiles in one file (`C_{n}_evaluated.json`, `C_{n}_coboundary.json`) as named by issues I06/I07, instead of the v5.0 `_<gb>` suffix.
6. `structure_constants` stores **ordered** pairs (both (X,Y) and (Y,X)), so anti-symmetry can be verified independently in I04.

#### Options considered
- *Store only X ≤ Y pairs (half the data)* vs *store all ordered pairs*: chose all ordered pairs — larger files (still small: < 2k entries for n=3) but makes I04's anti-symmetry check a real test rather than a tautology.
- *Keep κ/K inside `oscillator_relations`* (as the B(0,n) table hints) vs *top-level `central_elements`*: the mandatory unified rule fixes top-level.

#### Compatibility with B(m,n)
Documented as a key-by-key table in the spec: all structural keys (`basis`, `parity`, `generator_realization`, `structure_constants`) keep identical shape; differences are additive (`central_elements`, `dimension_formulas`, `metadata.notation`) or the deliberate fermion-key rename (`supplementary_fermion` → `fermions`).
