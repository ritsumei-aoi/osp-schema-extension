## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Design Decisions & Field Specifications

**1. Algebra Field for C(n+1)**

```json
{
  "family": "C",
  "m": 1,
  "n": n_value,
  "cartan_type": "C(n+1)",
  "alternative_notation": {
    "osp": "osp(2|2n)",
    "dimension_formula": "osp(2m|2n) with m=1"
  },
  "dimension": {
    "total": 2*n_value^2 + 5*n_value + 1,
    "even": 2*n_value^2 + n_value + 1,
    "odd": 4*n_value
  }
}
```

**Rationale**:
- `"family": "C"` distinguishes from B(0,n)
- `"m": 1` explicitly records fermionic pair count (fixed for all C(n+1))
- Dimension formulas verified against handover/notation.md (I01)
- Alternative notation clarifies osp form with explicit parameter interpretation

**2. Oscillator Generators**

```json
{
  "fermions": {
    "m": 1,
    "count": 2,
    "labels": ["a_1_p", "a_1_m"],
    "description": "Standard fermionic pair (a_1^+, a_1^-) with CAR: {a_1^-, a_1^+} = 1"
  },
  "bosons": {
    "count": 2*n_value,
    "n": n_value,
    "labels": ["b_1_p", "b_1_m", ..., "b_n_p", "b_n_m"],
    "description": "Bosonic oscillators b_k^± with k=1,...,n; CCR [b_k^-, b_l^+] = δ_{kl}"
  }
}
```

**Key changes from B(0,n)**:
- Replace `supplementary_fermion` key with `fermions` (signals different fermion type)
- Add `"m": 1` to indicate fermionic pair count
- Labels follow convention from I01: `a_1_p`, `a_1_m` (not `a_0`)

**3. Oscillator Relations**

```json
{
  "standard_fermion_anticommutators": {
    "description": "Canonical anticommutation relations for standard fermionic pair",
    "relations": {
      "hermitian_conjugate": "{a_1^-, a_1^+} = 1",
      "self_anticommutator_minus": "{a_1^-, a_1^-} = 0",
      "self_anticommutator_plus": "{a_1^+, a_1^+} = 0"
    }
  },
  "bosonic_commutators": {
    "description": "Canonical commutation relations for bosonic oscillators",
    "relations": {
      "same_type": "[b_i^±, b_j^±] = 0 for all i, j",
      "conjugate_pair": "[b_i^-, b_j^+] = δ_{ij}"
    }
  },
  "mixed_commutators": {
    "boson_fermion": "[b_k^±, a_1^±] = 0 for all k (deformed in Schema 2 by gb parameters)"
  }
}
```

**Key changes from B(0,n)**:
- Replace `supplementary_fermion_relation` key with `standard_fermion_anticommutators`
- Explicitly list all three CAR relations (improves clarity)
- Add note that boson-fermion commutators are deformed in Schema 2

**4. Central Elements (New Top-Level Key)**

```json
{
  "kappa": {
    "label": "κ",
    "parity": 1,
    "nilpotency": 2,
    "relation": "κ^2 = 0",
    "description": "Odd central element; parametrizes inhomogeneous deformations"
  },
  "K": {
    "label": "K",
    "parity": 0,
    "definition": "scalar 1",
    "description": "Even central identity element; identified with scalar 1 in all applications"
  }
}
```

**Placement**: Top-level key in Schema 1 (as required by I02)

**Rationale**:
- `κ` (odd, nilpotent) represents the formal parameter for inhomogeneous deformations
- `K` (even) is identified with scalar 1 per Bakalov-Sullivan convention; excluded from basis but recorded for completeness
- Explicit recording makes the algebraic setting transparent

**5. File Naming Convention**

- **Pattern**: `C_n_structure.json` where `n` is the **bosonic rank**
- **Examples**:
  - C(2) = osp(2|2) with $n=1$ → `C_1_structure.json`
  - C(3) = osp(2|4) with $n=2$ → `C_2_structure.json`
  - C(4) = osp(2|6) with $n=3$ → `C_3_structure.json`
- **Consistency**: Matches B(0,n) pattern: `B_n_structure.json`
- **Layers**: Schema 2-4 follow same pattern: `C_n_gamma.json`, `C_n_evaluated_<gb>.json`, `C_n_coboundary_<gb>.json`

#### Compatibility Analysis

**B(0,n) vs. C(n+1) Schema Mapping**:

| Field | B(0,n) | C(n+1) | Change type |
|-------|--------|--------|-------------|
| `schema_version` | "5.0" | "5.0" | same |
| `algebra.family` | "B" | "C" | value |
| `algebra.m` | 0 | 1 | value |
| `algebra.dimension` | formula | formula | updated formulas |
| `oscillator_generators` | supplementary_fermion + bosons | fermions + bosons | structure |
| `oscillator_relations` | supplementary + bosonic | standard_fermion + bosonic | key rename |
| `central_elements` | absent | present (κ, K) | new key |
| `basis` | 2n odd generators | 4n odd generators | size/labels |
| `parity` | maps all generators | maps all generators | different generator set |
| `generator_realization` | a_0 in formulas | a_1_p/m in formulas | substitution |
| `structure_constants` | computed from B relations | computed from C relations | recomputation |
| `metadata` | B-specific | C-specific | reference update |

**Backward compatibility**: Not applicable (C(n+1) is distinct family). However, schema structure is isomorphic — transformations are purely substitutional.
