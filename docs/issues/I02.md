## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Status**: complete

#### Decisions and Results

**1. `algebra` field**: Family set to `"C"`, m=1, with dimension formulas even = 2n²+n+1, odd = 4n. The `cartan_type` uses notation `C(n+1)` (e.g., `C(2)` for n=1). The `alternative_notation.osp` gives the osp form (e.g., `osp(2|2)`).

**2. `oscillator_generators`**: Two keys:
- `fermions`: type `standard_pair`, m=1, labels `[a_1_p, a_1_m]`, parity 1.
- `bosons`: count = 2n, rank n, labels `[b_1_p, b_1_m, ..., b_n_p, b_n_m]`.

**3. `oscillator_relations`**: Replaced `supplementary_fermion_relation` with `standard_fermion_anticommutators` containing {a_1^-, a_1^+} = 1 and self-anticommutators = 0. Mixed commutators updated to reflect [b_i^±, a_1^±] = 0.

**4. `central_elements`**: Top-level key containing:
- `kappa`: parity 1, nilpotent (κ² = 0), odd central element.
- `K`: parity 0, value = 1, even central identity.

**5. File naming**: `C_{n}_structure.json` where n is the bosonic rank. C(2) → `C_1_structure.json`, C(3) → `C_2_structure.json`, C(4) → `C_3_structure.json`.

**6. Compatibility**: Full compatibility table documented in `docs/json_schema_specification.md`, comparing each field between B(0,n) and C(n+1). The `structure_constants.result` field is extended to an array format to handle multi-term bracket results.
