# Issue I02-1: Schema 1 v5.0 extension for C(n+1)

## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Deliverable
`docs/json_schema_specification.md` created (new file). Schema 1 is fully specified
(§3), the B(0,n) compatibility table is in §4, validation rules in §5, and the layouts of
Schemas 2–4 are pre-specified in §6–§8 so that I05–I07 produce data conforming to one document.

#### Decisions (Requirements 1–5 and the mandatory unified rules)
1. `algebra`: `family="C"`, `m=1`, `n`=bosonic rank, `cartan_type="C(n+1)"`,
   `alternative_notation.osp="osp(2|2n)"`, and a new sub-key `dimension_formula` with the
   literal strings `"2n^2 + n + 1"` (even), `"4n"` (odd), `"2n^2 + 5n + 1"` (total), plus
   the numeric `dimension` block. Also records `even_subalgebra = "so(2) x sp(2n)"`.
2. `oscillator_generators`: exactly two keys, `fermions` (`m=1`, labels `a_1_p, a_1_m`) and
   `bosons` (`n`, labels `b_k_p, b_k_m`). `supplementary_fermion` removed.
   Option considered and rejected: keeping a `supplementary_fermion: null` placeholder for
   B-readers. Rejected because the unified rule says "two keys", and a reader that needs to
   dispatch can do so on `algebra.family`.
3. `oscillator_relations`: `standard_fermion_anticommutators` with `{a_1^-, a_1^+} = 1` and
   `(a_1^±)^2 = 0`; `bosonic_commutators` unchanged; `mixed_commutators` keeps
   `[b, a_1^±] = 0` and points to Schema 2 for the κ-deformation.
4. `central_elements` is a **top-level** key: `kappa` (parity 1, κ²=0, super-central) and
   `K` (parity 0, K = 1). Both flagged `in_basis: false`. Ambiguity noted: `B0n_definition.md`
   says κ is listed with parity 0 in the B(0,n) JSON; for C(n+1) I follow the mandatory
   rule (parity 1), which is also the mathematically correct parity for an odd central
   element.
5. File naming: `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated.json`,
   `C_{n}_coboundary.json` with `n` = bosonic rank (C(2) → `C_1_*`). Optional `_<profile>`
   suffix for extra gb profiles (mirrors B(0,n)'s `_<gb>` suffix).

#### Additions beyond B(0,n) (all additive, documented in §4)
* `basis.cartan`, `basis.pbw_order` (informative).
* `generator_realization.realizations.<X>.root` (informative root vector; `null` for Cartan).
* Schema 1 stores **both** orders $(X,Y)$ and $(Y,X)$ of every non-zero bracket so that the
  antisymmetry check of I04 is a real check. `Z` is restricted to basis labels in Schema 1;
  `"K"` is permitted as a target only in Schemas 2–4 (because the deformed bracket can
  produce constants — see I05).
