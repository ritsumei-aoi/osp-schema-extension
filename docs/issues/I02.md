# Issue I02-1: Schema 1 v5.0 extension for C(n+1)

**Date**: 2026-10-08
**Status**: closed

**Category**: proposal

## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Deliverable
`docs/json_schema_specification.md` created. Section 1 specifies every Schema 1 key for C(n+1)
with worked n=1 examples; §1.12 is the B(m,n) compatibility table; §0 fixes file naming.
Sections 2–4 are reserved for Schemas 2–4 (filled in I05–I07 so the spec stays in one file).

#### Decisions (mandatory unified rules all applied)
1. `algebra`: `family="C"`, `m=1`, `n`, `cartan_type="C(n+1)"`, `dimension.formulas` =
   `even: 2n^2 + n + 1`, `odd: 4n`, `total: 2n^2 + 5n + 1`; `even_subalgebra = "so(2) x sp(2n)"`.
2. `oscillator_generators`: exactly `fermions` (`m=1`, `a_1_p`, `a_1_m`) and `bosons` (`n`).
   No `supplementary_fermion`.
3. `oscillator_relations`: `standard_fermion_anticommutators` with `{a_1^-, a_1^+} = 1`,
   `(a_1^±)^2 = 0`; bosonic CCR unchanged; mixed `[b, a] = 0` (undeformed); plus relations of K, κ.
4. `central_elements`: top-level key with `kappa` (parity 1, κ²=0) and `K` (parity 0, K=1),
   both `in_basis: false`.
   *Ambiguity recorded*: `B0n_definition.md` §3 says κ is listed with parity 0 in the B JSON.
   The I02 mandatory rule (κ parity 1) wins for C(n+1); it is also the mathematically correct parity.
5. File naming: `C_{n}_structure.json` with `n` = bosonic rank (C(2)→`C_1`, C(3)→`C_2`, C(4)→`C_3`).

#### Options considered
* `schema_version`: keep `"5.0"` (chosen; layer architecture unchanged, family read from
  `algebra.family`) vs. bump to `"5.1"` (rejected: would force B readers to special-case a version
  that carries no structural change).
* `structure_constants` storage: one entry per unordered pair (B example style) vs. **all ordered
  pairs** (chosen) so the I04 anti-symmetry check tests the data rather than a derived convention.
* Constants in brackets: allow `Z="K"` in Schema 1 vs. **forbid** (chosen; the generator asserts no
  constant survives in $[\mathfrak g,\mathfrak g]$). `Z="K"` is allowed only in Schema 2+, where the
  κ-deformation genuinely produces constant terms (see I05).
