## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### Summary
Created `docs/json_schema_specification.md` (C(n+1) v5.0). §1 fully specifies Schema 1; §0 fixes file naming
for all four layers; §2–4 are filled in by I05–I07.

#### Decisions (mandatory unified rules applied verbatim)
- `algebra`: `family="C"`, `"m": 1`, `n` = bosonic rank, `cartan_type="C(n+1)"`, `dimension_formulas`
  {even: `2n^2 + n + 1`, odd: `4n`, total: `2n^2 + 5n + 1`} plus numeric `dimension`.
- `oscillator_generators`: exactly two keys, `fermions` (m=1, `a_1_p`, `a_1_m`) and `bosons` (rank n).
- `oscillator_relations`: `standard_fermion_anticommutators` ({a_1^-,a_1^+}=1, (a_1^±)²=0), `bosonic_commutators`
  unchanged from B, `mixed_commutators` = 0 undeformed (deformed value documented for Schema 2).
- `central_elements`: top-level key with `kappa` (parity 1, κ²=0) and `K` (parity 0, value 1, excluded from basis).
- File naming: `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated.json`, `C_{n}_coboundary.json`, n = 1, 2, 3.

#### Options considered
- Where to put κ, K: (a) inside `oscillator_relations` (B-style prose note) vs (b) top-level `central_elements`.
  The unified rule mandates (b); it also makes the parity of κ machine-readable.
- `structure_constants` storage: (a) only X ≤ Y (half), (b) all ordered pairs. Chose (b): a few hundred extra
  entries, but it makes graded antisymmetry testable in I04 directly from the file.

#### Ambiguity recorded
`B0n_schema_v5.md` says κ is listed "with parity 0" in `central_elements`, contradicting p(κ)=1 in
`B0n_definition.md` §3 and the I02 unified rule. Adopted parity 1 and documented the correction in the spec.

#### Compatibility
A key-by-key compatibility table vs B(0,n) v5.0 is in the spec: only the fermion keys are renamed/replaced and
`central_elements` is added; all other keys keep the B layout.
