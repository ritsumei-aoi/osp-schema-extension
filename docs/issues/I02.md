## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Deliverable:** created `docs/json_schema_specification.md` — a complete Schema 1 field
specification for C(n+1), plus a Schema 2–4 file-naming map.

**Design decisions and how the mandatory unified rules were met:**
1. **`algebra` field** — `family="C"`, explicit `m=1`, and `dimension.formula` records
   `even = 2n^2+n+1`, `odd = 4n`, `total = 2n^2+5n+1`, with the concrete (4,4,8)/(11,8,19)/(22,12,34)
   table for C(2)/C(3)/C(4). ✓
2. **`oscillator_generators`** — exactly two keys: `fermions` (`m=1`, labels `a_1_p,a_1_m`, CAR) and
   `bosons` (rank `n`, labels `b_k_p,b_k_m`). The $B(0,n)$ `supplementary_fermion` ($a_0$) key is
   removed. ✓
3. **`oscillator_relations`** — supplementary relation replaced by `fermionic_anticommutators`
   (`{a_1^-,a_1^+}=1`, `(a_1^±)^2=0`); bosonic CCR retained; `mixed_commutators` undeformed
   (`[b,a_1]=0`), to be deformed in Schema 2.
4. **`central_elements`** — promoted to a **top-level** key with `kappa` (parity 1, nilpotent) and
   `K` (parity 0, identity = 1). ✓
5. **File naming** — `C_{n}_structure.json` etc., `n` = bosonic rank (C(2)→`C_1`, C(3)→`C_2`,
   C(4)→`C_3`). ✓

**Structure-constant record shape** fixed as `{X, Y, Z, coeff, sign_rule:"graded"}`, bracket =
graded commutator in the oscillator algebra; central contributions recorded as `Z="K"`; only
`X ≤ Y` (PBW) records stored (antisymmetry recovers the rest). This is what I03 implements.

**Compatibility with B(m,n)** documented in a table: same `schema_version` 5.0 and same record
shapes; `family`+`m` are the discriminator selecting the fermionic sector; even-sector labels are
shared; odd labels are namespaced (`E_eps1_del*` vs `E_del*`), so no collisions; the new
top-level `central_elements` key is additive/backward-compatible.

All four completion criteria met.
