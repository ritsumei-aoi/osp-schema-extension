## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### 1. Specification Overview
The v5.0 JSON schema specification has been designed and written to `docs/json_schema_specification.md` following all mandatory rules:
- **`algebra` field**: Configured with `family: "C"`, `m: 1`, bosonic rank `n`, and explicit dimension formulas `even: "2n^2 + n + 1"`, `odd: "4n"`, `total: "2n^2 + 5n + 1"`.
- **`oscillator_generators`**: Structured with standard fermionic pair `fermions` (`m=1`, labels `a_1_p`, `a_1_m`) and `bosons` (rank `n`, labels `b_k_p`, `b_k_m`).
- **`central_elements`**: Designed as a top-level key containing `kappa` ($p=1$, $\kappa^2=0$) and `K` ($p=0$, central unit).
- **`oscillator_relations`**: Specified Canonical Anticommutation Relations (CAR) for $(a_1^+, a_1^-)$ and Canonical Commutation Relations (CCR) for $(b_k^+, b_k^-)$.
- **`generator_realization`**: Documented normal-ordered PBW form of all generators, with rational coefficient representation.
- **`structure_constants`**: Preserved graded bracket representation with entries `{"X", "Y", "Z", "coeff", "sign_rule": "graded"}`.

#### 2. Compatibility with $B(m,n)$
Backward compatibility considerations are documented in Section 3 of `docs/json_schema_specification.md`. The format extends $B(0,n)$ without altering the core computational contract for structure constants or deformation analysis scripts.

#### 3. File Naming Conventions
Confirmed unified naming across all four layers:
- Layer 1: `data/C_{n}_structure.json`
- Layer 2: `data/C_{n}_gamma.json`
- Layer 3: `data/C_{n}_evaluated.json`
- Layer 4: `data/C_{n}_coboundary.json`
where $n \in \{1, 2, 3\}$.
