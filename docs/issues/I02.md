## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Date**: 2026-10-10 — **Status**: closed (all criteria met)

Deliverable created: `docs/json_schema_specification.md` — complete v5.0
specification for C(n+1), covering Schema 1 normatively plus the Schema 2–4
formats consumed by I05–I07.

Decisions against the mandatory unified rules (all satisfied):

1. **`algebra` field**: `"family": "C"`, `"m": 1` explicit, dimension formulas
   `even = 2n^2 + n + 1`, `odd = 4n` recorded both as formula strings in
   `alternative_notation.dimension_formula` and as concrete numbers in
   `dimension` (verified table for n=1,2,3: 4|4, 11|8, 22|12).
2. **`oscillator_generators`**: exactly two keys — `"fermions"` (`m: 1`,
   labels `a_1_p, a_1_m`) and `"bosons"` (rank `n`, labels `b_k_p/m`). The
   B(0,n) `supplementary_fermion` key is removed entirely.
3. **`oscillator_relations`**: `standard_fermion_anticommutators` with CAR
   `{a_1^-, a_1^+} = 1` and `(a_1^±)^2 = 0` replaces
   `supplementary_fermion_relation`; bosonic CCR and mixed commutators kept
   with identical structure to B(0,n).
4. **`central_elements`**: top-level key holding `kappa` (parity 1, κ² = 0)
   and `K` (parity 0, K = 1). Note: `B0n_definition.md` §3 remarks that in
   the B schema κ was listed with parity 0 as a formal symbol; for C(n+1) the
   mandatory rule fixes parity(κ) = 1, which is also the mathematically
   correct parity (the deformation κ·γ must preserve total parity with
   parity-1 gb). Adopted parity 1.
5. **File naming**: `C_{n}_structure.json` with n = bosonic rank
   (C(2) → `C_1_structure.json`, C(3) → `C_2_...`, C(4) → `C_3_...`);
   analogous names for layers 2–4 (`_gamma`, `_evaluated`, `_coboundary`).

Backward compatibility with B(m,n) v5.0 is documented in a dedicated section
(key-by-key table): shared record formats are unchanged, `central_elements`
is additive, and fermionic-key renames are the only structural differences —
a reader that ignores unknown keys and treats basis labels as opaque strings
parses both families.

Verification: spec cross-checked against `B0n_schema_v5.md` key list (all
nine Schema 1 top-level keys defined, plus the new `central_elements`) and
against I01's basis lists (n=2 example embedded verbatim).
