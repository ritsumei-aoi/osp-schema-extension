## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Date**: 2026-10-09. Deliverable: `docs/json_schema_specification.md` (new, complete; Schema 1 fixed here, Schemas 2–4 pre-specified so that I05–I07 implement an agreed format).

#### Decisions per requirement

1. **`algebra`** — `family: "C"`, `m: 1`, `n`, `cartan_type: "C(n+1)"`, `alternative_notation.osp: "osp(2|2n)"`, `alternative_notation.dimension_formula: "osp(2m|2n) with m=1"`, an explicit `dimension_formula` object (`even: "2n^2 + n + 1"`, `odd: "4n"`, `total: "2n^2 + 5n + 1"`), numeric `dimension`, plus `even_subalgebra: "so(2) x sp(2n)"` and `rank: n+1`. Mandatory rule satisfied (`m: 1` and both formulas are explicit).
2. **`oscillator_generators`** — exactly two keys: `fermions` (`m: 1`, `labels: [a_1_p, a_1_m]`, parity 1) and `bosons` (`n`, labels `b_k_p/b_k_m`, parity 0). The `supplementary_fermion` key is removed, not renamed, so a B(0,n) reader notices the change.
   * Option considered: keep a `supplementary_fermion: null` placeholder for strict key-compatibility. Rejected: the mandatory rule names the two keys, and a null placeholder invites misreads.
3. **`oscillator_relations`** — `fermionic_anticommutators` (`{a_1^-, a_1^+} = 1`, `(a_1^±)^2 = 0`), `bosonic_commutators` (unchanged from B(0,n)), `mixed_commutators.boson_fermion = "[b_i^±, a_1^±] = 0 (undeformed)"`.
4. **`central_elements`** — top-level key with `kappa` (parity 1, `kappa^2 = 0`, super-central) and `K` (parity 0, `K = 1`), both `in_basis: false`. Note the B(0,n) document records κ with parity 0 in JSON; for C(n+1) the mandatory rule (parity 1) is adopted, and the parity bookkeeping for gb·κ is explained in spec §2.
5. **File naming** — `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated[_<profile>].json`, `C_{n}_coboundary.json`, with `n` = bosonic rank (C(2) → `C_1_*`). Confirmed in spec §0.

#### Additional design choices

* `schema_layer` integer added at top level (optional for readers) to make the 4 layers self-identifying.
* `basis` gains `pbw_order` (canonical index order used by Layers 2–4), `cartan`, and `roots` (label → root string). `basis.even` now holds $n+1$ Cartans (`H_1 … H_{n+1}`), `basis.odd` the $4n$ generators `E_eps1_del{k}_pp/pm/mp/mm`.
* `structure_constants`: stored for **all ordered pairs** so that graded antisymmetry is checkable from the file (decision recorded; the B(0,n) example shows a single entry and does not settle this).
* All coefficients are exact rational strings; C(n+1) needs no $\sqrt2$.
* Compatibility table (B(0,n) vs C(n+1)) written in spec §0; all B(0,n) keys are kept with the same semantics.
