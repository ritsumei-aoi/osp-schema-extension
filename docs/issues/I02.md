## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### 1. Schema 1 Field Design
The v5.0 Schema 1 specification for $C(n+1) = \mathfrak{osp}(2|2n)$ has been formalized in `docs/json_schema_specification.md` in adherence to all mandatory rules:
- **`algebra`**:
  - `family`: `"C"`
  - `m`: `1`
  - `n`: rank integer ($n \ge 1$)
  - `dimension_formulas`: `even`: `"2*n^2 + n + 1"`, `odd`: `"4*n"`, `total`: `"2*n^2 + 5*n + 1"`
  - `dimension`: `{ "even": ..., "odd": ..., "total": ... }`
- **`oscillator_generators`**:
  - `fermions`: `{ "count": 2, "m": 1, "labels": ["a_1_p", "a_1_m"], "description": ... }`
  - `bosons`: `{ "count": 2*n, "n": n, "labels": [...], "description": ... }`
- **`oscillator_relations`**:
  - Standard CAR for `a_1_p`, `a_1_m`: $\{a_1^-, a_1^+\} = 1$, $\{a_1^\pm, a_1^\pm\} = 0$.
  - Standard CCR for $b_j^\pm$: $[b_j^-, b_k^+] = \delta_{jk}$, $[b_j^\pm, b_k^\pm] = 0$.
  - Mixed: $[b_j^\pm, a_1^\sigma] = 0$ (undeformed).
- **`central_elements` (top-level key)**:
  - `kappa`: odd nilpotent central parameter ($p=1$, $\kappa^2 = 0$).
  - `K`: even central element ($p=0$, scalar value $1$).
- **`basis` & `parity`**:
  - Follows PBW ordering: $\kappa < [\text{odd}: 4n] < [\text{even}: 2n^2 + n + 1]$.
- **`generator_realization` & `structure_constants`**:
  - Lists normal-ordered oscillator words and non-zero graded brackets $[X, Y\} = \sum_Z c_{XY}^Z Z$.

#### 2. File Naming Convention
Unified convention fixed:
- Schema 1: `C_{n}_structure.json` where $n$ is bosonic rank ($n=1 \to C(2)$, $n=2 \to C(3)$, $n=3 \to C(4)$).
- Schema 2: `C_{n}_gamma.json`
- Schema 3: `C_{n}_evaluated_<gb>.json`
- Schema 4: `C_{n}_coboundary_<gb>.json`

#### 3. B(0,n) Compatibility Analysis
- Structural schema keys remain identical (`schema_version`, `algebra`, `oscillator_generators`, `oscillator_relations`, `basis`, `parity`, `generator_realization`, `structure_constants`, `metadata`), ensuring scripts and validation pipelines can digest both families with common parser routines.
- `central_elements` is formally unified as a top-level key.
- The discriminator `algebra.family` ("B" vs "C") drives family-specific dispatching.
