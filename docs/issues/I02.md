# Issue I02-1: Schema 1 v5.0 extension for C(n+1)

**Date**: 2026-10-08
**Status**: closed

**Category**: proposal
**Theme Working Branch**: study/thm01-R-fable51-b02-G

## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Decision summary (2026-10-08, no-gate: decided without human approval)**

Deliverable: `docs/json_schema_specification.md` (Sections 1-5 complete for Schema 1; Sections 6-8 reserved for I05-I07).

1. `algebra`: `family="C"`, `m=1`, `n`, `cartan_type="C(n+1)"`, `dimension` plus the mandatory
   `dimension_formulas` {even: "2n^2 + n + 1", odd: "4n", total: "2n^2 + 5n + 1"}, `rank=n+1`,
   `even_subalgebra="so(2) + sp(2n)"`.
2. `oscillator_generators`: exactly `fermions` (m=1, labels a_1_p, a_1_m, parity 1) and `bosons` (rank n, 2n labels).
   `supplementary_fermion` removed.
3. `oscillator_relations`: `standard_fermion_anticommutators` ({a_1^-, a_1^+} = 1, (a_1^±)^2 = 0),
   `bosonic_commutators` unchanged, `mixed_commutators` states the undeformed [b, a_1] = 0 and points to Schema 2.
4. `central_elements` is a **top-level key** with `kappa` (parity 1, kappa^2 = 0, super-central) and `K` (parity 0, K = 1).
   Options considered for kappa's parity: (a) parity 0 as in the B(0,n) v5 text, (b) parity 1 as in
   `C_inhomogeneous_definition.md` and the I02 mandatory rules. Chose (b): it is the only choice under which
   [b_j^s, a_1^σ] = -gb kappa is parity-consistent with scalar gb, and it is what the issue mandates.
5. File naming confirmed: `C_{n}_structure.json`, `C_{n}_gamma.json`, `C_{n}_evaluated.json`, `C_{n}_coboundary.json`
   with n = bosonic rank (C(2) -> `C_1_*`).
6. Additions beyond B(0,n) (all additive, documented in the compatibility table §3): `schema_layer`, `roots`
   (integer root vectors in the (eps, delta_k) basis), `algebra.rank`, `algebra.even_subalgebra`.
   `structure_constants` lists **all ordered pairs** so antisymmetry can be checked from the data (I04).
7. Compatibility: a B(m,n) reader needs a `family` switch, must read `fermions` instead of
   `supplementary_fermion`, and must tolerate the extra keys; B files remain valid with `m=0`.

**Verification.** The spec was written against the actual generated file `data/C_1_structure.json`
(generator `src/C_generators.py`, committed in I03); all example snippets in §2 and §5 are copied from
that file. Dimension table checked for n = 1, 2, 3: (4,4,8), (11,8,19), (22,12,34).
