## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Result**: `docs/json_schema_specification.md` created (the file did not exist, so it was created as the I02 deliverable). It defines all Schema 1 top-level keys for C(n+1), gives a compatibility table against B(0,n), and outlines Schemas 2 to 4.

**Decisions**

1. *Mandatory rules applied as written*: `algebra.m=1`; dims $2n^2+n+1$ and $4n$; `oscillator_generators` has `fermions` (`a_1_p`, `a_1_m`) and `bosons` (rank $n$); `central_elements` is top-level with κ of parity 1 and K of parity 0.
2. *Constant $K$.* K is recorded as the scalar $1$ and never as a basis element. A K component in a bracket is an error to report (see §1.9), not a silent drop.
3. *Structure constants format.* Kept the B(0,n) list format, with the first index ≤ the second, and the super-skew rule stated per entry.
4. *File naming.* `C_{n}_structure.json` with $n$ the bosonic rank, as mandated. `C_1` is $C(2)$.
5. *Unresolved in B(0,n) text.* The B(0,n) doc puts κ with parity 0 in `central_elements`, but κ is odd by `C_inhomogeneous_definition.md`. For C(n+1) the spec uses κ parity 1. This is a deliberate departure, recorded in the compatibility table.

**Verification**: Cross-checked each Schema 1 field name against the task list in `B0n_schema_v5.md` ("Task: Producing the C(n+1) Extension" table). All listed keys are covered. The JSON examples in the spec are hand-checked and will be validated against the generated files in I03.
