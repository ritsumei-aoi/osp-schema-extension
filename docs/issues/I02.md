## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**1. Design `algebra` field for C(n+1)**
Defined with `family="C"`, `m=1`, and proper dimension formulas (even: `2n^2 + n + 1`, odd: `4n`, total: `2n^2 + 5n + 1`).

**2. Design `oscillator_generators`**
Removed `supplementary_fermion` (from B(0,n)) and replaced it with a `fermions` key that lists `a_1_p` and `a_1_m` for $m=1$.

**3. Design `oscillator_relations`**
Introduced `standard_fermion_anticommutators` to store canonical anticommutation relations (`{a_1^-, a_1^+} = 1`).

**4. Determine `central_elements`**
Added a top-level `central_elements` key capturing the odd central element `kappa` (parity 1) and the even central element `K` (parity 0).

**5. File naming conventions**
Files are confirmed to be named according to the bosonic rank $n$ (e.g., `C_1_structure.json` for C(2), `C_2_structure.json` for C(3)).

**Execution Result**
The required specification has been written to `docs/json_schema_specification.md`, explicitly addressing all required unified rules and documenting the compatibility with the B(m,n) schema.
