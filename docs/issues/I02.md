# Issue I02-1: Schema 1 v5.0 extension for C(n+1)

**Date**: 2026-10-06

## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

**Decisions**
- `algebra`: family "C", m=1, explicit even/odd/total formulas (2n²+n+1, 4n, 2n²+5n+1) plus concrete dimension.
- `oscillator_generators`: keys `fermions` (m=1, labels a_1_p, a_1_m) and `bosons` (rank n); no supplementary fermion.
- `oscillator_relations`: CAR `{a_1^-,a_1^+}=1`, nilpotency, CCR, undeformed boson-fermion commutation.
- `central_elements`: top-level; κ parity 1 (κ²=0), K parity 0 (identified with scalar 1).
- Ambiguity recorded: `B0n_definition.md` says p(κ)=1 in the text but "listed with parity 0" in the schema note. Options: (a) copy parity 0, (b) parity 1. Chose (b), following `C_inhomogeneous_definition.md` and the mandatory rule (κ parity 1).
- Structure constants stored for all ordered pairs (both X,Y and Y,X) so I04 can test antisymmetry non-trivially. Alternative (store X<Y only) rejected because it would make the antisymmetry check vacuous.
- File naming `C_{n}_structure.json` (n bosonic rank), also `_gamma`, `_evaluated`, `_coboundary` for layers 2–4.

**Compatibility**: table in `docs/json_schema_specification.md` lists each B(0,n) key and its C(n+1) change; key names and encodings unchanged.

**Result**: `docs/json_schema_specification.md` created (Schema 1 complete; Schemas 2–4 sections to be appended in I05–I07).
