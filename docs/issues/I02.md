## Context & Background
The existing Schema 1 (algebra structure) was designed for B(m,n). Extending to
C(n+1) requires modifications to several fields while maintaining backward
compatibility. Issue I01 has finalized the basis and PBW ordering.

## Requirements
1. Design `algebra` field for C(n+1) (family="C").
2. Design `oscillator_generators` without supplementary fermion.
3. Design `oscillator_relations` for standard fermionic pair (CAR).
4. Determine `central_elements` (kappa, K) for C(n+1).
5. Define file naming conventions (e.g., `C_1_structure.json`, `C_2_structure.json`, `C_3_structure.json`).

### Mandatory unified rules (fixed for all runs)
- **Algebra Field**: explicitly include `"m": 1` and the dimension formulas `even`: `2n^2 + n + 1`, `odd`: `4n`.
- **Oscillator Generators**: two keys, `"fermions"` (with `m=1`, labels `a_1_p, a_1_m`) and `"bosons"` (with rank `n`).
- **Central Elements**: `central_elements` is a **top-level key**, containing `kappa` (parity 1) and `K` (parity 0).
- **File Naming**: `C_{n}_structure.json`, where `n` is the bosonic rank (e.g., C(2) uses `n=1`).

### Response

#### 1. Schema 1 Specification Creation
Created `docs/json_schema_specification.md` defining the complete v5.0 schema specification for $C(n+1) = \mathfrak{osp}(2|2n)$, covering:
- `schema_version`: `"5.0"`
- `algebra`: explicitly includes `"family": "C"`, `"m": 1`, rank `n`, `"cartan_type": "C({n+1})"`, dimension formulas: even $= 2n^2 + n + 1$, odd $= 4n$, total $= 2n^2 + 5n + 1$.
- `central_elements`: top-level key defining `kappa` (parity 1, $\kappa^2=0$) and `K` (parity 0, value 1).
- `oscillator_generators`: structured with `"fermions"` (`m=1`, labels `["a_1_p", "a_1_m"]`) and `"bosons"` (`n`, labels `["b_1_p", "b_1_m", ...]`).
- `oscillator_relations`: CAR for fermionic pair (`{a_1^-, a_1^+} = 1`, $(a_1^\pm)^2=0$), CCR for bosons, and mixed commutators.
- `basis`, `parity`, `generator_realization`, `structure_constants`, and `metadata`.

#### 2. File Naming Conventions
Confirmed unified naming convention:
- $n=1$: `data/C_1_structure.json` ($C(2) = \mathfrak{osp}(2|2)$)
- $n=2$: `data/C_2_structure.json` ($C(3) = \mathfrak{osp}(2|4)$)
- $n=3$: `data/C_3_structure.json` ($C(4) = \mathfrak{osp}(2|6)$)

#### 3. Backward Compatibility
The specification includes a direct mapping table comparing each field against $B(0,n)$ v5.0, detailing how existing tools can parse both families uniformly (e.g. key presence checks for `fermions` vs `supplementary_fermion`).
