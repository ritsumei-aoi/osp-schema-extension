#### 1. Representative assignment (Requirement 1)
**Chosen: `all_plus_one`** — all $4n$ parameters $\mathrm{gb}_{a_1^σ,b_k^s} = +1$, written to the
unsuffixed file `C_{n}_evaluated.json` as the issue suggests. Because γ is linear homogeneous
in gb (κ² = 0, verified in I05), any assignment is the corresponding linear combination of the
$4n$ unit profiles; `all_plus_one` therefore exercises every parameter at once and is the
natural representative. Alternatives implemented as named profiles so that I08 can switch
without code changes: `all_minus_one`, `alternating` ($\mathrm{gb} = σ\cdot s$),
`fermion_sign`, `boson_sign`, `row_plus` (only the $a_1^+$ row), `unit:<label>`, and
`custom` (explicit JSON values). The `alternating` profile is additionally emitted to
`C_{n}_evaluated_alternating.json` (suffix convention from I02 §1).

#### 2–3. Script and Schema 3 format (Requirements 2–3)
Each file follows `docs/json_schema_specification.md` §7: header copied from Schema 1/2,
`gb_assignment {profile, values}`, `evaluated_gamma` (records `X, Y, Z, coeff`, Z may be
`"K"`), and `deformed_structure_constants` — the complete deformed bracket table with
`kappa_order` 0 (= Schema 1) and 1 (= evaluated γ) records, i.e. 152 / 850 / 2368 records
for n = 1, 2, 3.

#### Consistency with Schema 2 (and Schema 1)
Four checks per file: (1) the stored γ equals an **independent recomputation** in the
oscillator engine with the numeric gb substituted before normal ordering (not after);
(2) it equals the substitution into the Schema 2 linear forms; (3) `kappa_order 0` records
equal Schema 1; (4) the numeric first-order cocycle identity on all $\dim^3$ triples.
