#### Decisions
1. **Representative assignments (Requirement 1).** Options: (a) a single profile (all +1);
   (b) one file per profile (`C_{n}_evaluated_<gb>.json`, B-spec style); (c) several profiles in
   one `C_{n}_evaluated.json`. Chose (c): the issue prescribes the file name `C_{n}_evaluated.json`,
   and I08 needs several qualitatively different profiles to look for trivial vs. non-trivial cases.
   Profiles (same names for every n):
   | name | gb assignment |
   |---|---|
   | `zero` | all 0 (control: undeformed) |
   | `all_plus` / `all_minus` | all +1 / all −1 |
   | `row_split` | +1 on row a_1_p, −1 on row a_1_m |
   | `column_split` | +1 on columns b_j_p, −1 on columns b_j_m |
   | `alternating_j` | (−1)^{j+1} |
   | `checkerboard` | sign(σ)·sign(s)·(−1)^{j+1} |
   | `unit_p_1_p`, `unit_m_1_m` | a single parameter = +1, rest 0 |
   Since γ is linear in gb (I05) these, together with the symbolic Schema 2, cover the analysis of
   arbitrary gb in I08.
2. **Format (Requirement 3).** Schema 3 stores only the κ-part (`gamma_evaluated`, incl. central
   `Z="K"` entries) per profile; the undeformed part is referenced via `structure_ref` to avoid
   duplication. Documented in `docs/json_schema_specification.md` §3.
