### Response

#### Representative gb assignments
Options considered: (a) only all +1; (b) all $2^{4n}$ sign vectors (4096 files for n=3 — impractical and unnecessary since γ is linear in gb); (c) a small set of structurally different profiles. **Chosen (c)**:

| Profile | gb_{σ,j,s} | Purpose |
|---|---|---|
| `allplus` (default) | +1 | the representative "all +1" case requested |
| `allminus` | −1 | global sign flip (tests linearity) |
| `checker` | +1 if σ = s else −1 | mixes signs between matching/non-matching oscillator signs |
| `rowsign` | +1 for a_1^+ row, −1 for a_1^- row | sign depends on fermion only |
| `single` | gb_{a1+,b1+}=1, rest 0 | unit vector — localizes the effect of one parameter |
| `zero` | 0 | undeformed control (trivial by definition) |

#### File naming decision
The issue asks for `C_{n}_evaluated.json` whereas the B(0,n) spec uses `B_n_evaluated_<gb>.json`. To satisfy both: the default profile (`allplus`) is written to `C_{n}_evaluated.json`, every other profile to `C_{n}_evaluated_{profile}.json`.

#### Implementation
`src/C_evaluate.py` reads Schema 1 and Schema 2 **JSON files** (not the generator code), substitutes the gb values and writes Schema 3 (format in `docs/json_schema_specification.md` §4): the evaluated γ (`evaluated_deformation`, incl. `K` entries) and the full deformed bracket (`evaluated_structure_constants`, `part` = `g`/`kappa`).

#### Verification (all 18 files)
For each file `check_schema3` verifies: (1) re-substitution of Schema 2 reproduces the stored γ, (2) the `g`-part equals Schema 1, (3) the evaluated deformed bracket satisfies the super-Jacobi identity of $L$ (κ-part of Jacobiator = 0 for all dim³ triples), (4) all labels belong to the Schema 1 basis (∪ K).
