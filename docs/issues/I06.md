### Response

#### Decisions
- **gb assignment.** Options: (a) a single profile (all +1) per file as B's `B_n_evaluated_<gb>.json`,
  (b) one `C_{n}_evaluated.json` holding several representative sign profiles. Chose (b) (file name as required by
  this issue) with `primary_profile = "all_plus"`. Profiles: `all_plus`, `all_minus`, `row_sign`
  (gb_{a1p,*}=+1, gb_{a1m,*}=−1), `boson_sign` (gb_{*,b^+}=+1, gb_{*,b^-}=−1), `alternating_j` ((−1)^{j+1}),
  `single_a1p_b1p` (one non-zero parameter, isolates a single column of the γ-map), `zero` (control).
  These cover sign patterns that distinguish the fermion row, the boson ± column and the mode j, which is what I08
  needs to test any gb-condition for triviality.
- Both the g-valued γ and the central κK part γ_K are evaluated (kept separate, as in Schema 2).

#### Implementation
`src/C_evaluate.py` substitutes the profile into the linear forms of `C_{n}_gamma.json`. For verification it also
recomputes every bracket through an independent path: the oscillator engine with the **numeric** gb inserted directly
into [b_j^s, a_1^σ] = −gb κ (new `gb_values` option in `C_oscillator.Oscillators`), and compares.
