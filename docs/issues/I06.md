### Response

**Implementation (2026-10-08, no-gate)**

Files: `src/C_evaluate.py`, `data/C_{n}_evaluated.json` (representative profile) and
`data/C_{n}_evaluated_<profile>.json` for n = 1, 2, 3 (21 files), `tests/test_C_evaluate.py`,
`docs/json_schema_specification.md` §7.

**1. Representative assignment and sign profiles.** Options considered: (a) a single all-+1 file,
(b) a family of sign profiles. Chose (b) with `all_plus` as the representative file named
`C_{n}_evaluated.json` (as the issue requests) plus six more profiles, because I08 needs evidence across
several gb assignments: `all_minus`, `row_sign` (+1 on the a_1_p row, −1 on the a_1_m row), `col_sign`
(+1 for b_j^+, −1 for b_j^-), `checkerboard` ((−1)^{row+col}), `single_pp` (only gb_a1p_b1p = 1) and
`zero` (undeformed control).

**2. Schema 3 content.** For each profile: `gb_assignment` (values + 2 × 2n matrix), `gamma_evaluated`
(Schema 2 linear forms evaluated, zeros dropped) and `deformed_structure_constants` — the complete
deformed bracket `[X,Y}_γ = Σ coeff κ^{kappa_power} Z` for all ordered basis pairs, so the file is a
standalone description of the deformed algebra. A `verification` block records the super Jacobi test of
L = g~ ⊕ κ g~ (built by `C_gamma.extended_algebra`) at the given gb values.

**3. Consistency with Schema 2 (and Schemas 1/4-readiness).** Verified by tests for all 21 files:
re-evaluating the Schema 2 linear forms reproduces `gamma_evaluated`; the κ⁰ part of the deformed table
equals Schema 1 and the κ¹ part equals `gamma_evaluated`; `verification.pass` is reproduced; for n = 1, 2
the stored deformed brackets coincide with an independent numeric run of the oscillator engine
(`checkerboard` profile).
