**Representative gb assignments** (options considered, with reasons):
- `all_plus`: every $\mathrm{gb}=+1$. Chosen as the mandated default; it is the simplest assignment and matches the instruction "e.g., all set to +1".
- `alt`: $\mathrm{gb}$ alternates $+1,-1$ in gb order. Added as a second profile so that I08 has a non-trivial sign pattern to compare. Rejected alternatives: random signs (not reproducible) and a single-entry profile (too degenerate).

**Implementation**: `src/C_evaluate.py`. It substitutes gb values into the Schema 2 linear forms and writes:
- `data/C_{1,2,3}_evaluated.json` (all_plus, the mandated Schema 3 file);
- `data/C_{1,2,3}_evaluated_alt.json` (alt).

Each file holds the $\kappa$-free brackets (copied from Schema 1), the numeric $\kappa$-part, and the profile values.

**Cross-check (data consistency with Schema 2)**: the evaluated $\kappa$-coefficients are compared entry by entry with a direct build of the algebra at the same numerical gb (`C_structure.build`, which uses the deformed oscillator relations). This is independent of the Schema 2 linear forms.

**Bug found and fixed in the harness**: the first cross-check reported `False`. The direct build had received gb keyed by strings instead of $(\sigma,j,s)$ tuples, so it silently compared against the undeformed algebra. The evaluated values were correct. After the key fix, every file reports `matches_direct_build = True`.
